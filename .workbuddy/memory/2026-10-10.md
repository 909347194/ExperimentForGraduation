### 另一处纠正：K=M−1 不是算法缺陷，是实验配置偏离
文档 §1(4) 设想的问题特征是 **|T_t| ≫ K_avail**（任务远多于机）。
exp01_smoke 却是 24 机 / 10 任务（**机远多于任务**），与该假设相反。
「机多任务少」时 `K=min(K_avail, M−1)` 确实浪费（10 任务只派 9 架）；
但在文档设想的 |T|≫K 场景下 K 会自然取满 K_avail，不成问题。
→ exp02/03 规模应改成任务 ≫ 机（如 60 任务 / 8 机）。

## 2.6「终点机巢进编码」改动方案（已出方案，待用户确认后动手）

### 编码设计
用 `uav_id` 哨兵值区分基因类型，不新增 Gene 字段（Gene 是 frozen dataclass）：
- `uav_id >= 0` 起始基因（UAV→任务）
- `uav_id == -1` 巡游基因（任务→任务）
- `uav_id == -2` **终止基因（新增）**，`target_id` = 机巢下标 b

每个 UAV 航次段末尾恰好一个终止基因。cost_vector 长度由 `K+M` 变为 `K+M+K`，
终止基因的分量**参与 mutate_population 的差分变异** ← 这才是"终点由进化决定"。

### 代价矩阵扩展（关键）
现有 `(K+M, M)`：上块 UAV→任务，下块 任务→任务。
扩展为 `(K+M, M+B)`：
- `[K:, M:]` = task_nest（任务→机巢，终止基因在此匹配）
- `[:K, M:]` = uav_nest（UAV 起点→机巢，供空航次用）
匹配时必须掩膜：任务匹配只许 `M` 前列，终止基因匹配只许 `M:` 列，否则任务/机巢语义混淆。

### 改动面（比最初预估大，共 5 处）
1. `representation/encoder.py` — `_generate_srp` 加终止基因；`Individual` 加
   `end_nests` 属性；`assignment` 跳过 `-2`
2. `representation/inverse_mapper.py` — `_inverse_phi_srp` 新增「终止阶段」；
   `_recalculate_srp_tour_costs` 处理 `-2`；扰动后规范化终止基因到段末
3. `representation/repair_rules/terminal_nest.py`（新）— 终止基因唯一性/有效性/修补
4. `cost/cost_matrix.py` — `build_pairwise_costs` 增出 `task_nest` / `uav_nest`
5. `solvers/dmde_solver.py` — 增加 `n_nests` 透传给 `inverse_phi`（约 5 行，
   **这是唯一要动"DMDE 本体"的地方**，只是参数透传，不碰算子）
6. `solvers/muas_stage.py` — `build_solution` 改读 `individual.end_nests`；
   `choose_end_nests` 降级为容量兜底（编码终点超容时改派）

### 风险
- 终止基因必须恒在段末，`_perturb_srp_tour` 的 insert/reverse 会打乱 → 扰动后统一规范化
- 空航次（UAV 无任务）时终止基因前驱是 UAV 起点，走 uav_nest 块
- 容量约束由适应度 penalty 引导进化规避，落地期仍保留硬校验兜底

### 备选方案 C（若时间紧）
不进编码，把 `choose_end_nests` 升级为容量感知最优分配，论文 §5(2) 写
「多机巢终点选择策略」而非「统一编码」。但会弱化创新点第 3 条。

## 2.6 已实现完成（终点机巢进编码）

### 编码设计（最终落地）
用 `uav_id` 哨兵值区分基因类型，**不新增 Gene 字段**（Gene 是 frozen dataclass）：
`≥0` 起始 / `-1` 巡游 / `-2` **终止基因**（`target_id` = 机巢下标）。
`cost_vector` 布局：`[0,K)` 起始 / `[K,K+M)` 巡游 / `[K+M,K+M+K)` 终止。
终止分量参与 `mutate_population` → 终点是**进化结果**。
注意：srp 加终止基因后个体长度由 `M` 变 `M+K`。

### 改动文件（6 个）
1. `representation/repair_rules/terminal_nest.py`（新）— 哨兵常量、
   `split_segments` / `normalize_srp_segments` / `repair_terminal_genes` / `extract_end_nests`
2. `representation/encoder.py` — `_generate_srp` 追加终止基因；
   `Individual.end_nests`；`assignment` / `srp_routes` 跳过 `-2`
3. `representation/inverse_mapper.py` — 新增「终止阶段」`_select_end_nests`
   + `_pick_nest_by_cost`（温度自适应）；扰动后强制 `normalize_srp_segments`；
   `_recalculate_srp_tour_costs` 跳过 `-2`
4. `cost/cost_matrix.py` — 增出 `task_nest` / `uav_nest` / `n_nests`
5. `solvers/dmde_solver.py` — 仅透传 `n_nests`（给 encoder / inverse_phi /
   apply_extinction），**未碰任何算子逻辑**
6. `solvers/muas_stage.py` — cm 扩列到 `M+B`；`build_solution(coded_end_nests=)`；
   `_choose_end_nests` 改为「编码为主、容量兜底」；evaluate 加 `individual` 参数

### 踩坑（改同类代码时必看）
1. **`horizon._subset_cost_build` 丢了机巢块** —— 它只裁 `uav_target` / `task_task`，
   新加的 `task_nest` / `uav_nest` 没带过去 → `n_nests` 判 0，终点没进编码。
   机巢块**列维不随任务子集变化**，只裁任务行；`uav_nest` 原样保留。
2. **`extinction._random_cost_vector` 长度不一致** —— 内部 `PopulationEncoder`
   没传 `n_nests`，生成 `M` 长而种群是 `M+K` → broadcast 报错。
   已给 `apply_extinction` / `_random_cost_vector` 加 `n_nests`。
3. **`end_nests` 可能含 `None`** —— `build_solution` 里要跳过，否则 `int(None)` 崩。
4. **评估缓存键必须含终点** —— 否则「同分配、不同终点」命中错误缓存。
5. 并行 Edit 同一文件会 `EBUSY`，要串行。

### 附带修复（原有 bug）
`_perturb_srp_tour` 的 `reverse` / `insert` 会把起始基因卷进子序列，
实测起始顺序 `[0, 2, 1]`。已用 `normalize_srp_segments` 在扰动后重建分段。

- 终点随进化变化：80 次采样 43 种组合；3 seed → 3 种终点
- 满泊位 32 机 + strict_capacity：无超容、无异常
- 三周期 `violations=[]`、`penalty=0`
- **消融（同 seed）：终点进编码 323.2km vs 启发式 331.0km，降 2.4%**
