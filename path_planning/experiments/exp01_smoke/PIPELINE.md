# exp01_smoke —— 单机单航次冒烟

## 这个实验回答什么

真实 Guangzhou 场景里，一条 2.8 km 的机巢间航段能不能在"走廊 → RRT → NLP →
独立复核 → 真几何净空"这条链上完整跑通，并且时间来自优化器而不是估算。
单机，所以没有冲突消解的戏份；它的价值是**把其余每一环压到可信**。

## 输入

| 文件 | 作用 |
| --- | --- |
| `config.yaml` | 本实验唯一参数来源（场景、建场、走廊、`PlanParams`、误差口径） |
| `uav_config.json` | 一架 M30T，机巢 0 → 机巢 1，`t0=0`，栖停 30 s |

航段：`nest0 (-890.7, 1350.3)` → `nest1 (-486.9, -1458.7)`，水平 2835 m；
起点 z = 地面 + 8 m，终点 z = 地面 + 18 m。

## 跑法（项目根下）

```powershell
$env:PYTHONPATH="."
& ".\.venv\Scripts\python.exe" -m path_planning.experiments.exp01_smoke.run
& ".\.venv\Scripts\python.exe" -m path_planning.experiments.exp01_smoke.audit
```

首次运行会建全域场（Guangzhou，85 s / 857 MB），落盘到
`path_planning/experiments/.cache/`；之后每个实验复用同一张场（键里带 origin /
spacing / shape / agl / pad / nofly / bias，参数变一位就换文件）。删掉缓存目录
只会让它重算，不影响正确性。

## 输出

`results/seed_0/`：

- `solution.json`：每条航迹的完整段表（`t0/t1/p0/v0/p1/v1`），可离线重建任意时刻位置；
- `metrics.json`：SDF 净空、真几何净空、复核结论、预算占用、协调轮次；
- `run_meta.json`：场是复用还是新建、建场/装配/规划耗时、场的 shape 与内存；
- `effective_config.json`：本次运行的参数快照（含全部 `PlanParams`）。

## 判据（audit 十项，缺一不算过）

1. 覆盖：航迹存在、起终点与请求一致、段时刻连续；
2. 复核：独立验证器通过（不是优化器自证）；
3. 真几何：棱柱净空 ≥ `clearance_m=6.0 m`；
4. 预算：按清单里的剩余续航 900 s / 航程 16 km 判；
5. 冲突：重新检测必须 0 对（单机实验中恒为 0，判据保留是为了四个实验同一套口径）；
6. 时间来源：交付航迹的 `time_source` 必须是 `trajectory`——`estimate`/`fallback`
   属降级交付，"零静默降级"要有判据守着，不能只靠人看；
7. 运动学裕度：水平速度 / 爬升率 / 下降率 / 合速 / 加速度 / 推力六项利用率 ≤ 1
   （公式与验证器同源，但报"用到几分"，1.0 = 贴边）；
8. 稠密净空：把采样步长从配置的 2 m 缩到 **0.2 m** 重算 SDF 净空，仍须 ≥ 6 m。
   验证器只保证"每 2 m 一个点都过"，稠密采样用来排除"最小值落在采样缝隙里"；
9. 分段边界：leg 数 = 1 + 停过的中间停留点数，且每个 leg 终点落在对应停留点上
   （≤1 mm）。本实验只有 1 个停留点、1 条 leg；多段的账由 `exp05_multileg` 承担
   （那里额外判"Σ leg 飞行/悬停/弧长 = 整条账"，防段间重复计时）；
10. 端点豁免：机巢 SDF 实测只有 +1.63 m，起降段物理上不可能 ≥6 m，故对端点 25 m
   豁免球内的点按 **2.0 m** 单独判，且与"稠密净空"互不重复计。豁免球外的点仍按 6 m。

## 实测（seed 0）

时长 244.72 s（含 30 s 栖停）、弧长 2867.9 m、飞行均速 13.36 m/s、
最大速度 14.71 m/s、SDF 净空 9.82 m、真几何净空 13.57 m、复核通过、
120 段、审计 **10/10**；预算占用 20.4%（244.7/1200 s），余量 955 s / 17.1 km。
单次规划约 4–5 分钟（场走缓存，建场 85 s 只在首次）。

**单机质量账**（全部由落盘航迹事后复算，不重跑优化器）：

| 指标 | 实测 | 读法 |
| --- | --- | --- |
| 时间 / 下界 | 244.72 / 242.44 s ⇒ **1.009** | 下界 = 弧长÷`v_max_plan`(13.5) + 悬停；0.9% 的余量说明时间几乎榨干 |
| 同一时长按 `v_max`(15) 的下界 | 1.106 | 合速度受爬升分量占用的那部分，正是 3D 路径的代价 |
| 绕行比 | 2867.9 / 2837.9 m ⇒ **1.0106** | 只比巢0→巢1 的三维直线多飞 1.0% |
| 水平速度利用率 | **1.000** | 水平速度贴边上限（`v_max_plan`） |
| 爬升 / 下降率利用率 | 0.975 / 0.972 | 爬升略紧，下降同量级 |
| 合速度利用率 | 0.981 | 14.71 / 15.0 |
| 加速度利用率 | **1.000** | 加速度也贴上界（峰值 3.0 m/s² 量级） |
| 比推力利用率 | 0.540 | 推力远未用满（M30T 有富余） |
| 竖直加速度余量 | 0.750 m/s² | 离"托不住重力"的下限还有 0.75 |
| 稠密净空 | 0.2 m 与 2 m 采样同为 **9.82 m** | 最小值不是采样缝隙里的空洞 |
| 弧长 − 弦长和 | 0.9 m / 2868 m | 离散化弯曲极小（段够密，路径近直） |

两条贴边（水平速度、加速度）是 min ΣΔt 的正常结果：时间最优解会把"免费的"
约束用满；推力只用一半，说明限制来自运动学而非动力。净空 3.8 m 的余量不是浪费，
是 4/4/2 m 网格 SDF 的保守性——稠密采样证明它没有"看起来 9.82 其实 7.0"的水分。


飞行带上界从 `ground_min + agl_max` 改成 `ground_max + agl_max`（103.30 → 173.63）
后，RRT 窗口的竖向解域高了一倍：同一条航段从 245.38 s / 2861.3 m / 净空 7.92 m
变成上面这组数——时长略降、净空明显变好，因为 RRT 多了"从楼顶上方跨过去"的选择，
不必贴着楼侧缝钻。这类数字必须在改口径后重跑，不能沿用旧值。

`config.yaml` 里 `n_nodes: 120`、`clearance_samples_per_segment: 8` 不是随手取的数：
60 节点（间距约 48 m）+ 段内 3 采样点时，复核最小净空实测 **−9.7 m**——节点满足
净空不等于航迹满足净空，曲线在节点之间穿了楼。按段长扫过几档后，只有 120/8
（段内约束间距约 2.6 m，与复核 2 m 同量级）能过；因此 km 级城市长航段必须
120/8，代价就是单段 4–5 分钟。这条教训写在 `docs/architecture.md` §3.2。

## 已知边界

- 终点真高 18 m 低于部分楼顶，RRT 必须在窗口内绕，走廊半宽按 10% 水平距离给
  （本段约 142 m）；半宽过窄会把可解航段判成 `RRT_NO_PATH`。
- 飞行带 `agl_range_m: [3, 100]` 会落到 NLP 的 z 上下界：下限 `ground_min + agl_min`、
  上限 `ground_max + agl_max`，本次实测 `[5.30, 173.63]`。不给这一条时，
  位置是自由变量、目标只有 min ΣΔt，NLP 会把航迹爬到 208 m AGL——既出了低空
  口径，也会让冲突层把它当成"另一个高度层"从而漏判。
- 起点豁免圈 25 m、圈内阈值 2.0 m：机巢处 SDF 实测只有 +1.63 / −0.63 / +1.47，
  按 6 m 判会死在起点自检上（见 `docs/architecture.md` §4）。
- 单机结果不构成对冲突层的证据；那部分由 exp02 承担。
