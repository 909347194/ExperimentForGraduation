# exp01_smoke —— 多机多轮 tour 规划冒烟（无巢口径）

## 这个实验回答什么

`path_planning` 的整条设计能不能在真实 Guangzhou 场景里跑通，并且**不止跑单机**：

1. **tour**：每机一条"起点 → 途经点 → 终点"的多停靠点航次，逐段过完整流水
   （走廊 → RRT 多初值 → 时空 NLP → 独立复核 → 全域交付闸）；
2. **多机**：轮1 两机同批规划，新—新冲突协调（让路只改几何、时间随几何重解）；
3. **多轮（周期）**：轮2 在 `t0 = cycle_length_s = 240 s` 起飞，约束从
   "DEM + 建筑"变成"DEM + 建筑 + **轮1 已发布航迹**"（`TrajectoryRegistry`）——
   新机在旧机仍在飞的时间窗里规划，新—旧冲突由**旧侧冻结、新侧让路**消解；
4. **不依赖 task allocation**：tour、起始点全部由本实验自造（`uav_config.json`），
   没有任何机巢概念（`nest_id` / `home_nest` / `nest_above` 不存在）。

单机冒烟的全部流水被覆盖：覆盖/复核/真几何/预算/冲突/时间来源/运动学裕度/
稠密净空/分段边界十项照旧，"端点豁免球"换成更严的**端点无豁免全量判**。

## 设计：两轮四机 + 两处必撞

航点全部选在 201（exp07 已验证锚点）北侧的干净航带上，z=60 m 绝对高程
（逐点实测 SDF/棱柱 ≥ 8 m，agl ∈ [3,100]）：

| 点 | 坐标 (x, y, z) | 角色 | SDF / 棱柱 (m) |
| --- | --- | --- | --- |
| P_B | (−587.8, −756.5, 60) | UAV1 终点悬停 500 s（**必撞靶**） | 37.4 / 30.0 |
| S1 | (−699.2, −268.4, 60) | UAV1 起点 | 25.2 / 25.1 |
| V1 | (−655.8, −514.6, 60) | UAV1 途经（悬停 60 s） | 27.1 / 27.3 |
| S2 | (−601.4, −149.6, 60) | UAV2 起点 | 50.2 / 30.0 |
| V2 | (−575.3, −297.4, 60) | UAV2 途经（悬停 120 s） | 26.7 / 29.1 |
| M2 | (−638.5, −613.1, 60) | UAV2 途经（0 s，引路径入干净带） | 19.6 / 19.7 |
| E2 | (−560.3, −1056.3, 60) | UAV2 终点 | 20.3 / 21.2 |
| S3 | 同 S1 | UAV3 起点（轮2，与 S1 不同时刻） | 25.2 / 25.1 |
| E3 | 同 E2 | UAV3 终点（轮2，与 E2 不同时刻） | 20.3 / 21.2 |
| S4 | (−650.0, −259.8, 60) | UAV4 起点（轮2 对照机） | 27.6 / 27.8 |
| E4 | (−606.6, −506.0, 60) | UAV4 终点 | 16.6 / 16.4 |

**必撞布局**（故意造的，审计里有对应判据）：

- **轮1 新—新**：UAV2 的 `M2→E2` 段以 **25.0 m 垂距**（同 z 层）掠过 P_B，
  时段 ~[171, 212] 正落在 UAV1 的终点悬停 [~113, ~613] 内 → 冲突必发，
  协调层改 **UAV2**（机号大的让路），只弯几何、不改 UAV1 的冻结时间；
- **轮2 新—旧**：UAV3 的 `S3→E3` 段以 **25.0 m 垂距**掠过 P_B，
  时段 ~[240, 307] 同样落在悬停窗内 → 新—旧冲突必发，旧侧（UAV1，机号小）
  冻结、UAV3 让路；
- **UAV4 对照**：远离冲突区（距 P_B 走廊 ≥ 250 m、与 UAV3 走廊相距 50 m 且
  时间错开），预期 0 冲突——用来证明"没造冲突的地方就是干净的"。

悬停时长（60/500/120/30 s）不是随手数：它们决定时间窗覆盖，使两次掠过必然
落进 UAV1 的悬停窗（裕量 ≥ 60 s），把"必撞"从赌时序变成确定性设计。
非设计的"悬停点 × 异机航线"邻近对逐对核过（全部 ≥ 117 m 或时间窗不重叠），
防止出现"悬停端点被卡死 → 让路无解"的死局。

## 输入

| 文件 | 作用 |
| --- | --- |
| `config.yaml` | 本实验唯一参数来源（场景、建场、走廊、`PlanParams`、误差口径、周期 240 s） |
| `uav_config.json` | 4 架 M30T + 4 条 tour（`round`/`t0`/`start`/`via`/`end`，全 ENU 坐标） |

`t0` 必须等于 `(round-1) × cycle_length_s`（写死校验；周期是决策节拍，不是飞行容器）。
`via` 里 `service_time_s=0` 的途经点不产生悬停段，结构上并入相邻 leg（审计按此对账）。

## 跑法（项目根下）

```powershell
$env:PYTHONPATH="."
# 0) 只验点位（秒级，先看选址口径是否仍成立）
& ".\.venv\Scripts\python.exe" -m path_planning.experiments.exp01_smoke.run --check-points
# 1) 规划（先自动做点位预检，再跑两轮；首轮建全域场 ~85 s / 857 MB 后走缓存）
& ".\.venv\Scripts\python.exe" -m path_planning.experiments.exp01_smoke.run
# 2) 审计（从落盘 JSON 复算，不信规划器自证）
& ".\.venv\Scripts\python.exe" -m path_planning.experiments.exp01_smoke.audit
# 3) 出图出表（只读 results，不重跑规划）
& ".\.venv\Scripts\python.exe" -m path_planning.experiments.exp01_smoke.build_figures
& ".\.venv\Scripts\python.exe" -m path_planning.experiments.exp01_smoke.build_tables
```

点位预检失败会**直接停**（不烧几十分钟规划才发现点位贴楼）；
`--skip-point-check` 仅供排查编排问题，正式跑不要加。

## 输出 `results/seed_0/`

- `solution.json`：逐轮结果（PlanResult 段表、让路机号、既有航迹快照、协调记录）；
- `metrics.json`：逐轮逐机指标 + `cross_round` 跨轮证据（触发冲突对、旧侧冻结、
  时间重叠、busy_until/prune 账）；
- `round_trace.json`：逐机票（时刻/时长/闸）+ 协调前冲突明细（配对、最小距离、CPA 时刻）；
- `round_trajectories.json`：键 `"轮:机号"`，可直接喂 `support/scene_3d.py`；
- `run_meta.json` / `effective_config.json`：轮次表、场信息、耗时、参数快照；
- `figures/P01_multi_round_3d.{png,pdf}`、`tables/exp01_round_results.{csv,tex}`、
  `tables/exp01_cross_round.{csv,tex}`。

## 判据（audit，逐项独立否决）

**逐轮通用**（覆盖 / 票自洽 / 复核 / 真几何 ≥ 6 m / 预算 / 端点净空 ≥ 6 m 无豁免）；
**逐机质量**（时间来源 = trajectory / 运动学裕度 ≤ 1 / 0.2 m 稠密净空 ≥ 6 m /
分段边界 ≤ 1 mm / 单机质量账）；**冲突**（逐轮交付集 0 对 + 全局终检 0 对）；
**跨轮**（本实验的灵魂）：

1. 必撞/轮1 新—新触发：协调前冲突 ≥ 1；
2. 必撞/轮2 新—旧触发：协调前**新—旧**冲突 ≥ 1（min_distance、CPA 时刻入表）；
3. 旧侧冻结：轮2 协调后既有航迹逐段不变（`old_changed` 为空）；
4. 在飞中规划：轮2 新航迹与既有航迹时间窗重叠 > 0；
5. 状态账：`busy_until == t_end`（服务时长不双计）；`prune` 摘除的航迹确实已落地。

## 选址与点位调整口径

点位不是拍脑袋：在设计区域用**与实验同距 [4,4,2]** 的局部场实测
（`build_occupancy` + `build_sdf` + 棱柱净空），逐点过 SDF/棱柱 ≥ 8 m、
agl ∈ [3,100]；每条 tour 直线走廊 2 m 采样 min SDF ≥ 6 m；
必撞垂距、悬停点对异机航线的邻近约束逐对核算（阈值 38 m 或时间窗不重叠）。

换点位时按同一口径走：改 `uav_config.json` 坐标 → `run --check-points` 复核 →
再跑。注意 P_B 东侧 x ≳ −500 m 是**静态禁飞区**（全区间等值、全高度），
干净走廊只有 P_B 南北这条航带（20 m 格俯视图：航带核心 SDF ≥ 24 m）。
必撞垂距控制在 20–25 m：太深（<10 m）让路档位吃紧，太浅（>30 m）冲突不触发。

## 已知边界

- 协调层"冲突对里只改机号大的那台"是写死口径，本实验用**轮2 机号严格大于轮1**
  （3、4 > 1、2）来实现"旧侧冻结、新侧让路"；要支持反向需改 `methods`，本实验不越界。
- 同一机号只允许一条 tour（`TrajectoryRegistry` 不允许同机两条未结束航迹）；
  起降点复用（S3=S1、E3=E2）靠时间窗错开，检测器按弦时间分离判安全。
- 时间表（悬停窗、掠过时刻）是设计值；实测以 `round_trace.json` 的
  `pre_conflicts` 为准。若新—旧触发为 0，run 会响亮告警并指向最常见原因：
  **掠过段爬高**——目标悬停在 z=60，若新航迹在目标上空 z ≳ 80 掠过，垂向差超出
  椭球 z 半轴（15 m）就不会判冲突。处置：把该轮 `t0`/途经悬停按 trace 实际时刻
  平移 ±30 s、或检查 RRT 初值是否被推高（真高带 [3,100] 下 min ΣΔt 本应贴着
  z=60 的平直干净带走）；审计的「必撞触发」会一直红到触发为止。
  （粗场距/低迭代的开发配置下实测过这种爬高：12 m 体素把航带挤窄，初值绕到
  z≈100，冲突静默消失——这也是必撞判据必须进审计的原因。）
- 单种子（seed 0）冒烟口径；多 seed 扫描是后续实验的事。
