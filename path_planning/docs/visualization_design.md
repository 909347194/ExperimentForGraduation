# 可视化设计（带时间戳的 4D 航迹）

> 术语见 `../README.md` §1.1：**周期**＝上层滚动决策；**航次**＝一架机一个周期的一次出行；
> **航段**＝航次内相邻停靠点之间；**轨迹段**＝航段内部的三次 Hermite 最小段。
> 本模块交付的是带时间戳的 trajectory，可视化要回答的不只是"飞过哪里"，更是
> "**何时在哪、和谁在何时可能重叠、上一周期遗留的航迹与本周期新航迹在哪衔接**"。

---

## 1. 三层信息拆解

可视化必须同时覆盖下面三层，缺一层就答不全上面的问题：

| 层 | 回答什么 | 画什么 | 失败后果 |
|---|---|---|---|
| **空间** | 在哪飞、能不能飞 | 建筑体块、无人机位置、航迹几何 | 只看俯视地图看不出建筑间净空与竖直让路 |
| **时间** | 什么时候在哪、谁占着空域 | 每段航迹的时间区间、周期边界、遗留 vs 本周期 | 静态图无法表达"上一周期起飞、此刻仍在空中" |
| **冲突** | 和谁在何时接近、怎么解掉的 | CPA 时刻与机对、最近距离/判阈、让路处置 | 只画两条线看不出两机是否同时在场 |

**没有单一"4D 绘图函数"能干净覆盖这三层。** 必须做视图组合：
一个 3D 空间-时间视图看几何与接近，一个共享时间轴看占用区间，一个冲突清单看事件与处置。
三者读同一份数据、彼此联动，而不是各画各的。

---

## 2. 三视图组合

| 视图 | 回答 | 内容 | 技术 |
|---|---|---|---|
| **① 3D 时空态势** | 空间 + 与谁接近 | 建筑棱柱（合并为单个 mesh）＋航迹；本周期与上一周期遗留**分色**；冲突航段高亮；时间切片滑块 | PyVista（现有 `exp*/support/scene_3d.py`） |
| **② 共享时间轴** | 时间占用 | 每架机一条横条＝一个航次的 $[t_0,t_{\text{end}}]$；**竖线标周期边界**；冲突时刻竖标；遗留段用不同填充 | Matplotlib 横条图（无需新库） |
| **③ 冲突事件清单** | 每个冲突怎么解 | 一行一事件：CPA 时刻 / 机对 / 最近距离 / 判定半径 / 亏欠 / 让路档位 / 是否清零 | 表格渲染（读契约 `conflicts[]`） |

三个约束：

1. **横条的时间基准是绝对时刻**，不是相对某航次的本地时间——只有绝对时刻才能把遗留航迹和新航迹放在同一把尺子上。
2. **遗留航迹只读不改**：视图里它用固定样式（灰/虚线），即使冲突也不让它变色表示"被让路"——实际让路的永远是本周期航迹。
3. **空间视图的时间切片**只控制"显示哪些点"，不改变冲突判定；判定早已由方法侧算好写进契约，视图不重算。

---

## 3. 数据契约：视图的唯一输入

方法侧落盘一份 `visualization.json`，三个视图**都只读它、互不算数**。这样改渲染不动方法、改方法不动渲染。

```
visualization.json
├─ trajectories[]   机号 / 航次 id / 周期 id / t0,t_end / 采样点(x,y,z,t) / origin=current|legacy
├─ conflicts[]      cpa_time / 机对 / 位置 / min_distance / radius / kind / deficit / 让路档位 / resolved
├─ intervals[]      机号 / [t_start,t_end] / 周期 id / 航次 id
└─ cycles[]         决策时刻 t_decision（周期边界竖线的位置）
```

字段口径与现有代码对齐：

| 契约字段 | 来源 | 说明 |
|---|---|---|
| `t0` / `t_end` | `Trajectory.t0` / `.t_end`、`HermiteSegment.t0/t1` | 绝对时刻，段间共享端点 |
| 采样点 | 沿轨迹段按弧长采样（与 `global_recheck._polyline_of` 同法） | 不用"只取节点"——节点只有两端点，画不出曲线 |
| `min_distance` / `radius` / `cpa_time` / `kind` | `PairVerdict` | 冲突证书原样落盘，视图不重算 |
| `deficit` | `radius + eps − min_distance` | 判阈亏欠，正越大越危险 |
| `origin` | 周期注册表在 `t_decision` 的在飞集合 | `legacy`＝上一周期遗留（不可动），`current`＝本周期新航迹 |
| `cycles[].t_decision` | `loop.cycle_length_s` 推进的决策时刻 | 时间轴竖线位置 |

`conflicts[].kind` 区分**周期内竞争**与**跨周期遗留**：前者机对都属于本周期，后者一方 `origin=legacy`。
两类在时间轴上的标注颜色不同，避免把"撞上自己人"和"同期互斥"混成一张图。

## 4. 联动（最后接）

三视图各自能独立画之后，再接联动。共用一个"当前时刻"状态：

| 操作 | 联动效果 |
|---|---|
| 点冲突清单某一行 | 3D 视图跳到该 `cpa_time`、高亮冲突机对与位置；时间轴游标移到同一时刻 |
| 拖 3D 时间切片 | 时间轴游标同步移动；清单只保留该时刻仍有效的事件 |
| 点时间轴某条占用横条 | 3D 视图只显示对应航次/周期，其余淡出 |

实现要点：联动只改"显示状态"（当前时刻、选中机号），**不改契约数据、不触发重规划**。
跨周期遗留段在联动中始终以 `legacy` 样式呈现，高亮也不改变它的"不可动"标记。

---

## 5. 落地顺序

1. **定契约**：先让规划链路把四段数据（轨迹 / 冲突 / 占用区间 / 周期边界）落进 `visualization.json`；
2. **三个视图各自实现**：3D 用现有 PyVista，时间轴用 Matplotlib 横条，清单即表格渲染；此步三视图互不依赖，可分别验证；
3. **最后接联动**：统一"当前时刻"状态，做 事件 ↔ 3D 游标 ↔ 时间轴游标 的双向同步。

不引入新依赖：现有 PyVista + Matplotlib 足够覆盖三视图。
MovingPandas / Kepler.gl 等面向"大规模轨迹回放"的方案，在只有两三个实验、每周期至多几架机的规模下用不上。

## 6. 当前边界（一句话）

方法侧的结构化输出尚未全部就绪：冲突证书目前主要活在审计与落盘诊断里，
`visualization.json` 还没由生产流程落盘（跨周期新—旧冲突已接入检测，见 README §3.3）。
本设计按"数据齐全"规划，**先把契约定下来**，视图就能在数据补齐后直接接入，不必改结构。
