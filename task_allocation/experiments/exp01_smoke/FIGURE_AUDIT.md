## 3. 质量评估

### 3.1 数据利用率：严重浪费

| 已落盘资产 | 现有图用了多少 |
|---|---|
| `per_seed`：**5 seed × 3 cycle 全量**（约 29 KB） | **只用 3 个标量**（completion_rate / total_cost / total_reward），合成 1 张 mean±σ 图 |
| `summary`：14 个字段 | 4 个 |
| `cycles[].muas`：19 个字段（含 `violations`/`penalty`/`coded_end_nests`） | 8 个 |
| `cycles[].selection`：18 个字段 | 5 个 |
| `metrics.fleet`：UAV 状态快照（idle/busy/charging/fault） | **0 个**（从未画） |

**最刺眼的一处**：`per_seed` 里 5 个 seed 的**完整周期数据**（每个 seed 都有自己
的 `cycles[]`、`summary`）是全实验最贵的产物，却只被压缩成 3 个数字各画一个点。
`seed_summary` 的 `_PANELS` 硬编码仅 3 项，`cycle_feasible_rate`、`n_completed`、
`n_infeasible_delivery`、`avg_wait` 等**同样有 mean/std 的指标全被丢弃**。

### 3.2 渲染规范：不统一

| 问题 | 实测 |
|---|---|
| **版面宽度不一致** | 最窄 `geo_task_lifecycle` 5.86 in ↔ 最宽 `seed_summary` 13.8 in，**跨 2.4 倍** |
| 后果 | `theme.py` 全局字号相同，同宽缩放后图内字号观感差 2.4 倍，多图并排不协调 |
| **无矢量图** | `results/figures/` 只有 PNG；旧 `.pdf` 在库中标记为已删除，`run.py --pdf` 未重建 |
| **图例遮挡** | `cycle_metrics` (a) 面板图例压住柱体；`cycle_metrics` (d) "求解耗时"标签与柱顶重叠 |
| 像素密度 | 180～422 dpi（同宽 6.5 in 计），**均高于 150 dpi 可用线，不算糊**，但非"论文级统一" |

### 3.3 实验设计对该图集的硬约束（非绘图问题，但影响图能否成立）

- **周期数只有 3**（`PIPELINE.md` E5）：所有"演化"图只有 3 行/3 点，
  `geo_evolution`、`geo_task_lifecycle` 的趋势判断力接近为零，"稳态"无从谈起。
- **10/11 张图只画代表 seed（seed 42）**（E7）：结论的稳健性无法从过程图读出。
- **事件驱动从未触发**（E6）：`replan_context`、`events`、`released_by_fault` 全为 0/空，
  ⑨ 维度无图是**数据缺失**而非绘图缺失——开 `faults` 前画也无意义。
- **关键约束惰性**（E1）：容量最大占用 4 = 上限未越界、航程违约恒 0、预筛不生效
  → 即使补了 ⑦⑧ 的图，图上也会是"一路全绿"，**证明不了机制在工作**。
  即：**想补图，得先设计能咬合的实验**。
