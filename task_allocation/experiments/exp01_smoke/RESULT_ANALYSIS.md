> 口径基线：覆盖门禁双开（`coverage_gate=true` + `lexicographic_coverage=true`）、`prune_zero_reward=false`、`λ=0.1`、K_mean=10、3 seed（42/43/44）

## 1. 一句话结论

**方法链路（任务选择 → MUAS 求解 → 覆盖门禁判定 → 周期执行）不变量全部闭合。** 三个 seed 均满足终局守恒、淘汰恒为零（结构性保证）、硬约束零违反；`audit_correctness.py` **25/29 PASS、4 项 WARN**（已知低危口径差异），退出码 0，方法闭环与理论口径一致 ✔。

**需如实披露的口径代价**：3 seed 最终完成率 **59.33±0.94 / 60 = 98.9%±1.6%**，**并非恒为 100%**——seed_42 因容量受限有 2 个任务滞留池内（其中 1 个超期）始终未交付。这是「无超期淘汰」口径的**显式取舍**：过期任务不出池、不强制丢失（A2 结构性保证 `n_eliminated≡0`），代价是容量/时窗不足时完成率不保满。该滞留由审计 `n_overdue_ever` WARN 显式暴露，供人眼复核，而非被静默丢弃。

## 2. 正确性验证（核心，三 seed 全过）

| 验证项 | 判据 | seed42 | seed43 | seed44 | 结论 |
|---|---|---|---|---|---|
| **终局守恒** | arrived = completed + eliminated + unreachable + remaining | 60=58+0+0+2 | 60=60+0+0+0 | 60=60+0+0+0 | ✅ |
| **A2 结构性保证** | eliminated = 0（无超期淘汰口径，出池仅=完成/不可达） | 0 | 0 | 0 | ✅ |
| **硬约束** | n_hard_violations_total = 0 | 0 | 0 | 0 | ✅ |
| **物理不可达** | n_unreachable = 0 | 0 | 0 | 0 | ✅ |
| **废飞航程** | infeasible_wasted_path_m = 0（无物理不可行交付） | 0 | 0 | 0 | ✅ |

## 3. 三项主口径指标解读

| 指标 | 含义 | seed42 | seed43 | seed44 | 说明 |
|---|---|---|---|---|---|
| `completion_rate_final`（η_final） | 到达任务的最终完成率（**论文主口径**） | 0.967 | 1.0 | 1.0 | 3 seed 均值 98.9%±1.6%，非恒满 |
| `on_time_rate_final` | 交付集条件按时率 = 按时交付 / 已交付 | 0.759 | 0.800 | 0.750 | TW 为**软约束**，允许迟到换完成 |
| `correct_exec_rate` | 逐周期未加权正确执行率（过程指标） | 0.706 | 0.778 | 0.596 | 随随机实例波动较大 |

**关键语义区分（论文写作务必厘清）**：
- `η_final ≈ 0.97–1.0` 但 `on_time_rate_final ≈ 0.75–0.80`，中间落差即 **12–15 个迟到但已完成**的任务。这是设计预期——覆盖门禁宁递延不废飞、TW 以软惩罚（`w_late=0.01`）容许超时完成。
- `correct_exec_rate`（0.60–0.78）显著低于 `η_final`，因它计「逐周期准时出动」、而 `η_final` 计「最终是否完成」。二者**不同义、不同分母**，不可混用（正是口径审查删掉同名键的原因）。
- **`η_final` 不恒为 100%**：seed_42 有 2 个任务因单周期装填容量（K=10、每轮装 20）与窗口约束终局仍未排上，滞留池内（其中 1 个已超期）。这是「无超期淘汰」口径的诚实代价，须在方法章明述，不可误读为缺陷——它代表「宁可滞留、绝不静默丢弃」。

## 5. 覆盖门禁机制工作验证（软窗口径）

| 验证点 | seed42 | seed43 | seed44 | 含义 |
|---|---|---|---|---|
| n_gate_rescued（救回数） | 0 | 0 | 0 | 本次无不可行任务需救回（正常，因本就不产生废飞） |
| n_skip（S 内可装未装） | 0 | 0 | 1 | 门禁**几乎无误杀**——可装任务全被选中 |
| n_capacity_shortfall | 3 | 6 | 4 | coverage gate 正常排除超容量/不划算任务，递延至后续周期 |

## 6. 候选池验证（支撑「候选池该富」）

`cand_hit_rate = Σn_selected / Σn_cand`：
- seed42：**0.782**，seed43：0.857，seed44：0.903

候选池普遍富余（命中率 0.78–0.90，即约 10–22% 候选未被选），MUAS 有充足选择空间，直接支撑论文「候选池该富、避免 MUAS 无米之炊」的声明。seed_42 命中率最低（0.782），与其容量受限、积压最重一致——候选多但装填容量触顶。

## 9. 审计 4 项 WARN 解释（非缺陷）

| WARN | 来源 | 性质 | 处置 |
|---|---|---|---|
| **超期滞留诊断** `n_overdue_ever>0` | seed_42：1 个任务 latest 后仍滞留池内 | 调度失配信号（容量/时窗），**滞留≠丢失** | WARN，人工复核调度（窗口过紧 / 选择漏斗是否误杀），不阻断交付 |
| D 评价口径分裂 | 种子确定性 late 标记 vs 评价口径 ETA−latest 有 ≤30s 微差（seed42 cycle1 task2 差 30.1s；seed44 task18 差 32.6s） | 口径分裂，不翻转判定 | 已知，记于审计铁律注释 |
| D 迟到秒数残差 | 记录与重算迟到秒差被容差 `max(20s,2%)` 吸收 | soft-TW 大超时，属预期 | 已知，不修正 |
| M 段长方向性差异 | ETA（对称缓存）vs 代价矩阵（有序）有 <1% 方向性差（seed42 1 段 / seed43 3 段 / seed44 6 段） | 去/回程缓存不对称 | 已知低危，不影响航程守恒（O 项 PASS） |

> 四项均**不涉及守恒破坏或判定翻转**，是「口径分裂 / 数值微差」类，与审查文档 §A–§E 的预期一致。新增的「超期滞留诊断」WARN 是 07f23eb 口径下 `n_eliminated` 退化为结构性恒真断言后，补回的**真实运行时滞留检测**——它把「可完成任务机制性未完成」的可观测信号从失效的 A2 断言迁到 `n_overdue_ever`。

## 10. 对论文写作的提示

1. **主口径用 η_final（completion_rate_final）**，配 `on_time_rate_final` 作交付集条件率；`correct_exec_rate` 仅作过程佐证，不与前两者混用。
2. **完成率不恒为 100%**：须明述「无超期淘汰」口径——过期任务不出池、不强制丢失，容量/时窗不足时以「滞留」形式暴露（本台 seed_42 留 2），由 `n_overdue_ever` WARN 标记。这是设计取舍，非缺陷。
3. **覆盖率受机巢地理布局影响**：seed44 的 s_coverage_rate=0.95 提示「S 内可覆盖」非满，论文应说明覆盖率随 nest 布局变化，而非恒为 1。
4. **TW 为软约束**：完成率高、准时率中等的「落差」是设计特性（换来完成率），需在方法章明述，避免误读为缺陷。
5. **候选池富余（cand_hit_rate 0.78–0.90）**可直接作为「候选池该富」的实证数据引用。
6. **瓶颈在容量**：max_backlog=30 说明 10 架 UAV / 单周期装 20 是吞吐上限，可作为「机队规模敏感性」的引子（exp05/exp06 展开）。
