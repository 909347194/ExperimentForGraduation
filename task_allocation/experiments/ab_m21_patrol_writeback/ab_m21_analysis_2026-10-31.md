# M2-1 段内巡游序 Lamarckian 回写 · 三档 A/B 分析报告

日期：2026-10-31　｜　数据：`60:1` / `40:2` / `20:3` 三档，各 3 实例 × 2 种子 = **6 配对，共 18 对**
对照：M2-1 **关 (OFF)** vs **开 (ON)**，同实例几何 + 同求解器种子配对 ⇒ ON/OFF 差值的唯一来源是 M2-1

---

## 0. 一句话结论

> **M2-1 确实是「情境性增益」，但"情境"比设计稿 §6.5 说的更具体：它在单周期场景下 100% 不触发，
> 只在多周期滚动、且某个实例恰好被修复链重排了段内序时才显现 —— 触发率 6/18（33%），
> 触发时最大 −6.47% 路径成本，但也出现过 +2.32% 的劣化。
> 三档均值趋势单调，但 |mean| 远小于 std，**n=6 下没有任何一档达到统计显著**。
> 建议：维持默认关闭，先补「固定 N、只变周期数」的受控实验，再用新加的回写诊断计数器做归因。**

## 3. 逐配对明细（这才是真实结构）

**path_cost，Δ = ON − OFF**

| 实例·种子 | 60:1 | 40:2 | 20:3 |
|---|---|---|---|
| 2000·11 | 0.00 (0%) | **−302.46 (−3.36%)** | 0.00 (0%) |
| 2000·22 | 0.00 (0%) | **−201.63 (−2.33%)** | 0.00 (0%) |
| 2001·11 | 0.00 (0%) | 0.00 (0%) | 0.00 (0%) |
| 2001·22 | 0.00 (0%) | 0.00 (0%) | −23.78 (−0.27%) |
| 2002·11 | 0.00 (0%) | **+172.12 (+2.32%)** | −113.45 (−1.65%) |
| 2002·22 | 0.00 (0%) | 0.00 (0%) | **−468.57 (−6.47%)** |

三个结构事实：

1. **60:1 六对全部逐位相等（Δ ≡ 0）** —— 不是"增益很小"，是**一次都没触发**。
2. **触发是「实例 × 种子」两级开关**：同一实例在不同种子下可能一个触发一个不触发（t40·2002：seed11 劣化、seed22 不动；t20·2002：seed11 −1.65%、seed22 −6.47%）。⇒ 效应是随机的，取决于该次搜索恰好产生了怎样的基因型/表型错位。
3. **触发≠有益**：6 次触发里 5 胜 1 负，增益最大 −6.47%，最差 +2.32%。

## 4. 为什么单周期必然不触发（机理解释）

这不是巧合，是链条推出来的：

```
单周期场景
  └ 所有任务在本周期到达、本周期执行 ⇒ 没有跨周期滞留 ⇒ 没有累积等待
      └ 几乎没有任务逼近 latest ⇒ _reorder_for_deadlines 缺少重排动机
          └ 修复解保持 gene 编码给出的段内序 ⇒ 修复序 == 原基因型序
              └ 「没有新信息可写回」⇒ M2-1 退化为恒等操作 ⇒ Δ ≡ 0

多周期场景
  └ 任务滞留跨周期、部分逼近 latest ⇒ 的确发生段内重排
      └ 但能否写回还要过 _segment_matches：段基因任务集 ≡ 修复解航线集
          └ 只要该段有一个任务被剔除/改派 ⇒ 整段回写作废，退回 M1
              └ ⇒ 只有「重排了、且集合没动」的那些段才生效 —— 概率性命中
```

`_segment_matches` 要求集合**严格相等**是关键：航空孟utation 里 `_repair_range` / `_consolidate` 动一个任务就全段作废。
这与上一轮 mount 场景实测 `seg_match = 0/660` 完全一致 —— 那次也是单周期口径。

## 5. 局限：周期数与任务数被纠缠在一起 ⚠

三档同时改了两个变量 —— **每周期任务数 60→40→20 与周期数 1→2→3 是绑着变的**。所以「增益随周期数单调」这句有两种都成立的机理解释，本实验**无法区分**：

- **解释 A（累积截止压力）**：周期越多 ⇒ 滞留越久 ⇒ 截止压力越大 ⇒ 重排越多 ⇒ M2-1 越有用。
- **解释 B（航程长度）**：每机航线越短 ⇒ 一个段被剔除/改派的概率越低 ⇒ `_segment_matches` 越容易成立 ⇒ 触发率越高。

**必须的受控补充实验**：固定每周期任务数（如 20），只扫周期数 `1 / 2 / 3 / 4`。
若增益仍随周期单调 ⇒ A 成立（这是可写成论文的设计依据）；若不变 ⇒ B 才是主因。

另外 **n=6 严重欠功效**：t20 的 t 值仅 −1.46（p ≈ 0.2）。按观察到的量级，要达到常用功效需 30+ 配对/档。

## 6. 今天的配套设施：回写诊断计数器

上面第 3 节的「是否触发」是从 **Δ 是否为 0** 反推的。这是间接证据。今天已把直接证据做进代码：

```python
from task_allocation.methods.muas.solvers.evaluator import (
    writeback_stats, reset_writeback_stats,
)
reset_writeback_stats()
...  # 跑一次求解
print(writeback_stats())
# {'called':…, 'm1_start':…, 'patrol_off':…, 'non_srp':…,
#  'hard_violation':…, 'seg_match':…, 'seg_mismatch':…, 'exc':…}
```

`seg_match` / `seg_mismatch` 按**段**计数，能直接回答「六松弛 Γ 到底有没有真的写回过」。
纯观测、不参与任何控制流 ⇒ **无条件 bit-exact**（326 测试全过）。

**下一步该花的 30 分钟**：带着计数器重跑 20:3 与 60:1 各一对，验证
「60:1 ⇒ seg_match ≡ 0」与「20:3 有增益的配对 ⇒ seg_match > 0」两个预测。
预测成立，第 4 节的机理就从"推断"变成"实测"。

## 7. 结论与处置建议

| 结论 | 依据 |
|---|---|
| M2-1 **不能**作为普适改进转正 | 18 对中 12 对完全不动；有益 pairs 仅 5；出现过 −1 次劣化 |
| 但它是**真实机制**，不是实现 bug | 触发时的增益（−6.47%）远超噪声；Δ≡0 与 `_segment_matches` 严格相等判据完全吻合 |
| 适用面可刻画 | 「存在跨周期截止压力、且修复链重排后集合未被改动」的实例子集 |
| 单周期/离线口径下可直接忽略 | 60:1 六对逐位相同，等价于 OFF |

**建议动作（按性价比）**：

1. **维持默认关闭**（`lamarckian_patrol_writeback=False`）—— 现状合理，证据支持。
2. **补受控实验**：固定每周期任务数扫周期数，区分解释 A / B。这是把它写成论文增量最需要的一张图。
3. **用计数器复验机理**（第 6 节），把第 4 节从推断升为实测。
4. **若要提升触发率**，工程上是放宽 `_segment_matches`：现做法是「集合不等 ⇒ 整段退回 M1」，
   可改为「只对交集部分做段内序回写」。这条改动的收益与副作用需单独标定，不在本次结论内。
