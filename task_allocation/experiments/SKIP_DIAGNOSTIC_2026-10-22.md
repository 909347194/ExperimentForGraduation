## 判定

- 全局 S 内漏装率：34/2020 = **1.68%**（最差格 K10_arr2.5_lc0.1_s42 为 4.3%）
- urgent 强制任务全局：完成 448、淘汰 125、未决 21
- 恒等式校验（执行过又淘汰应为 0）：Σ = 0

### 三个结构性发现

**1. 非积压域的 deferred 是策略性推迟，不是失败。** arr≤10 六格淘汰全 0、urgent 全完成，
deferred 周期多数「有空闲机」（def_cycles_idle 2~3 个）——任务本周期不装是等更优班次/位置，
后续周期均被完成（残留 0~2 个 = 周期末到达的运行边界）。**覆盖门禁在这些域不仅零收益，
还可能有害**：强迫早装会推高航程与迟到（第二层目标被无谓牺牲）。

**2. 积压域的 deferred 周期全部满载（11/0、10/0 ⇒ part=K）。** 12~14 个漏装全部发生在
10 架 UAV 全派满的周期 ⇒ 不存在「空闲机可开班」的 voluntary_skip 通道，漏装更接近
tour 插不进（capacity_shortfall）或主动等窗。⇒ **门禁在积压域的真实增量大概率 < 2.5% 的上界**。

**3.  urgent 死亡任务死时 slack 中位 346s、最大 596s（34 个 >300s）——有窗却没装上。**
但结合 part<K=0/24（全周期满载）与 61 个淘汰「从未执行」，死因是**容量与选择层名额**
（到达 25 > 名额 20），不是「能插没插」。289 次标记 / 189 个任务 / 61 死 ⇒ 同一任务被
多周期反复标记（防饥饿在工作，但终刀名额装不下）。

### 投入判定

- **门禁作为完成率工具：增量上界 ≤2pp（积压域 0.787→0.807），非积压域 ≈0 或负。**
  考虑满载周期占比，真实增量预计 <1pp ⇒ 完成率动机弱，不支撑求解器重构的投入。
- **门禁作为机制叙事（消 m 标定病、三分账、硬约束化）仍有独立价值**，但排在 P4 成本 polish 之后。
- **精确分账值得做且便宜**：最小 instrumentation（落盘 S 成员 id / S 内 deferred id /
  per-UAV tour，两行，零求解行为改变）+ 补跑 arr25 一格（~1.8h）+ 离线一阶检验。
  回答两个问题：① 12~14 个 deferred 中 voluntary_skip vs capacity_shortfall 的构成；
  ② 61 个 urgent 死亡任务中「进过 S 没装」vs「从未进 S」的构成——这是论文机制表的关键行。
  **执行时机：等后台 4 格（ckm21O/JHqkJI）完成后**，避免 CPU 争用污染 solve 指标。

> 注：S 内漏装是 voluntary_skip 的**上界**（其中可能含物理装不下的 capacity_shortfall，
> 现有落盘无 S 成员 id 与 tour 结构，无法二分）。精确分账需最小 instrumentation。
