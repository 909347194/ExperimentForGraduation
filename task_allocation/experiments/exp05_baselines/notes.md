## 目的

在 **同一场景、同一指标口径、同一 seed 协议** 下，把本文完整方法与
**构造性基线 / 关键设计变体** 对照，回答：

1. 是否明显好于随机/贪心一类朴素策略？（M0 vs B1/B2/B3）
2. 分配层使用 **DEM 三维代价** 相对 **欧氏距离** 是否改变方案与指标？
   （M0 vs D0——同架构对照，只换代价/距离函数）
3. 朴素策略下三维代价是否仍有影响？（B2 vs B2e）
4. 与经典 **VRPTW 启发式**（硬时间窗插入）的差异来自哪里？

**本实验不宣称领域 SOTA 排行榜**；未实现的算法不出现在正式结果表中。

## 公平性协议（对照的有效性边界）

各臂共享（逐位一致）：

1. **同一滚动外壳**：任务池 / 机队状态 / 完成闸门 / 事件 / 收敛早停 /
   第一阶段动态任务选择（`methods/rolling` + `methods/selection`）；
2. **同一任务到达序列**：同 seed 生成的任务实例与到达时刻表，各臂独立
   深拷贝副本（`run.py` 逐臂重建实体），互不污染；
3. **同一硬约束定义与评价**：交付解一律过
   `SelectiveMUASProblem.check_feasible` / `problem.evaluate` 记账，
   metrics 字段与 exp01 逐字段同口径；
4. **同一 seed 协议**：5 个 seed（42–46），报告均值 ± 标准差。

各臂差异**仅**在（二选一）：

- **第二阶段搜索引擎**：DMDE（搜索 + 解码修复链 + polish + 方案 A 终点）
  vs 构造式启发式（一次成型，构造期即硬可行，贪心终点选巢）；
- **代价/距离模型**：DEM 垂直切面三维航程 vs 三维直线（D0 / B2e）。

**必须写明的口径**（写作注意）：

- 基线在**同一滚动外壳**内每周期被调用（非"基线也原生滚动"）；
  第一阶段选择是共享前端——对照回答的是「给定同一候选集，第二阶段
  搜索/建模差异带来什么」，选择层贡献由 exp02 / exp04（M1）回答。
- 构造式基线走**预构建解通道**（`SolverResult.extra["solution"]`）：
  其解不经过本文方法的解码修复链（合并/航程修复/覆盖补全/reorder）与
  polish——基线的构造策略就是其方法本身；唯一共享的是评价函数。
- B3 的硬时间窗是经典 VRPTW 假设，与生产口径「迟到不是废飞、按 L/W
  折减计奖」**故意不同**——两臂的差异正是这一机制差的体现，不是 bug。
- 终点机巢：B1/B2/B3 逐机贪心（容量余量优先、代价最小，无跨机协调）；
  M0/D0 走方案 A（容量约束下最小费用流联合最优）。

## 完成率口径与不可达归因（2026-10-25 修订）

**完成率不是性能指标，是正确性不变量。** 论文主表不应拿它做方法间对比
（所有臂都应为 1.000，零区分度），应改用按时率 / 航程效率 / 奖励产出 /
吞吐；完成率保留为审计断言（见 `exp01_smoke/audit_correctness.py` A2）。

### 三层集合与指标定义

| 集合 | 定义 | 判定时机 |
|---|---|---|
| 到达集 N | 全部到达任务 | 注入时 |
| 物理可达集 A_geo | ∃ 巢 n：`2·d_DEM(n, i) ≤ R_max`（**静态、与机队状态无关**） | 入池一次性 |
| 可完成集 A | `A_geo` 减去「机队服务不可达」 | 每周期滚动 |

- **完成率** `η_final = |完成| / |A|` ⇒ 机制保证**恒为 1.000**。
- **不可达率** `= |N \ A| / |N|` ⇒ 场景属性（机队配置 × 任务分布匹配度），
  有信息量，可进主表作场景特征列。

### 两类不可达归因（分母的合法排除项，单列计数）

| 键 | 含义 | 判定 |
|---|---|---|
| `n_unreachable_geo` | **静态几何不可达**：所有机巢往返航程都超满电可及 | `static_unreachable`，入池判定 |
| `n_unreachable_service` | **机队服务不可达**：几何可达，但连续 `service_patience`（默认 4）个周期无可用 UAV 在往返航程内 | 滚动层 `_update_service_stall`，典型为**机队漂移致空巢** |

### 为什么必须分开（exp05 seed43 实证）

旧口径把预筛的「最近**可用** UAV 往返超限」一律记 `exceed_round_trip_range`
（物理不可达）。机队漂移后空巢任务（最近巢 4 往返 74 km ≤ 80 km 续航，但
巢 4 无机、最近可用机在 51–68 km 外）被每周期误拒，于是：

> 既不进 `UNREACHABLE`（**分母照算**）、又每周期被拒（**分子不计**）
> ⇒ 完成率虚低为 0.950，且无法解释（既非物理约束、也非机制缺陷）。

2026-10-25 起预筛按「最近**机巢**」判几何可达性（与 `static_unreachable`
同源同尺）：往返超限但几何可达 ⇒ `no_uav_in_range`（服务不可达），连续
`service_patience` 周期无改善 ⇒ 按 `reason="service"` 出池。效果（M0
seed43）：`n_unreachable_service=3`、`n_unreachable_geo=0`、
`n_remaining_pool=0`、`η_final=1.000`，终局守恒
`60 = 57 + 0 + 3 + 0` 闭合。

### 写作注意（§3.5.4）

- **不可达率是机队配置的属性，不是任务的内在属性**——换巢布局/航程就变，
  论文须连同场景参数一起报告。
- 「迟到算完成」与「不可达」是两件独立的事：前者是软窗口径（时间窗），
  后者是能力边界（几何/机队）。二者不可混述。
- 若审稿人质疑「完成率恒 1 无区分度」：正面回应——这正是设计目标
  （可完成必完成），区分度由时效/效率类指标承担；未完成被**显式归因**
  而非静默丢弃，本身就是可审计性贡献。

```text
task_allocation/methods/
├── muas/solvers/muas_stage.py  # run_selective_muas(..., solver=None) 注入

experiments/exp05_baselines/
├── config.yaml           # exp01 同构场景 + methods: 对照臂

```

- `run_selective_muas` 的 `solver=None`（默认）= DMDE 主算法，行为逐位
  不变（pytest 220 例全过，含新增 `test_baselines.py` 6 例）；
- 注入求解器若返回预构建解（`extra["solution"]`），交付解跳过解码修复链
  / polish / memetic 档案；否则退回 assignment 解码通道（兼容未来
  "只换搜索引擎"式基线）。

## 实测结果（2026-10-25 全量：6 臂 × 5 seed，新口径）

数据源 `results/summary.csv`（每臂 5 seed + mean 行）与 `<ARM>/summary.json`。
30 个 arm×seed 格子守恒律 `n_arrived = n_completed + n_unreachable +
n_remaining_pool + n_eliminated` 全部闭合（60 = 57/58/59/60 + 归因项）；
`n_eliminated ≡ 0`（无超期淘汰口径），`n_unreachable_geo ≡ 0`（本场景无静态
几何不可达任务：任务均在某巢 80 km 往返航程内）。

### 主表（5 seed 均值±标准差）

| 臂 | 求解器/代价 | η_final | 按时率 | 奖励产出 | 总航程 km | 服务不可达 | s 覆盖 |
|---|---|---|---|---|---|---|---|
| M0 本文 | dmde / DEM | **1.000±0.000** | 0.770±0.050 | **0.898±0.038** | 1427±138 | 1.0 | 0.990±0.009 |
| D0 同架构 | dmde / 欧氏 | 1.000±0.000 | 0.777±0.047 | 0.890±0.033 | 1265±18 | 1.8 | 0.992±0.011 |
| B1 随机 | random / DEM | 1.000±0.000 | 0.598±0.054 | 0.811±0.044 | 2444±268 | 0.4 | 0.974±0.020 |
| B2 贪心 | greedy / DEM | 1.000±0.000 | 0.720±0.054 | 0.877±0.031 | 1513±59 | 0.0 | 1.000±0.000 |
| B2e 贪心 | greedy / 欧氏 | 1.000±0.000 | 0.731±0.034 | 0.868±0.036 | 1499±34 | 0.4 | 1.000±0.000 |
| B3 VRPTW | vrptw / DEM | **0.957±0.029** | **1.000±0.000** | 0.961±0.027 | 1510±136 | 0.2 | 0.506±0.225 |

求解耗时（mean）：M0/D0 ≈ 335–345 s/seed；B2/B2e ≈ 65 ms；B3 ≈ 11 ms；
B1 ≈ 5 ms。DMDE 以约 4 个数量级的求解时间换 anytime 质量，论文须同时报告。

### 口径修复不动基线数字（防「漂白」质疑）

同一批场景，修复前（`2d2598f` 提交，旧口径）与修复后逐 seed 对比：

| 臂 | 修复前 η（pool=滞留未归因） | 修复后 η（svc=服务不可达出池） | 变化 |
|---|---|---|---|
| M0 | 1.000 / 0.950 / 0.967 / 1.000 / 1.000 | 1.000 ×5 | 滞留 3/2 改判服务不可达出池 |
| D0 | 0.933 / 0.950 / 0.967 / 1.000 / 1.000 | 1.000 ×5 | 同上 |
| B1 | 0.983 / 0.983 / 1.000 / 1.000 / 1.000 | 1.000 ×5 | 同上 |
| B2e | 1.000 / 1.000 / 0.967 / 1.000 / 1.000 | 1.000 ×5 | 同上 |
| B3 | 0.933 / 0.967 / 1.000 / 0.950 / 0.917 | 0.933 / 0.967 / 1.000 / 0.966 / 0.917 | **逐位不变** |

B3 的 13 个未完成任务（4+2+0+2+5）**几何可服务**（有可用 UAV 在往返航程
内），只是硬时间窗装不下——不排除出分母，完成率如实记 0.957。即口径
修复只把「机队漂移空巢」从静默滞留改判为显式归因，**没有任何一个臂的
调度失败被洗白**。

### 关键发现（论文可用）

1. **完成率对本文方法是正确性不变量**（5/5 seed 恒 1.000），区分度由
   按时率（M0 0.770 vs B1 0.598）与航程效率（B1 2444 km vs M0 1427 km）
   承担——主表不要用完成率排序。
2. **B3 的 1.000 按时率是「拒单」换来的**：配额利用率 0.539（M0 0.668）、
   s 覆盖 0.506（M0 0.990）、平均积压 11.2（M0 9.3）、13/60 任务弃置。
   硬时间窗 vs 软窗+顺延的权衡在此可量化。
3. **欧氏对照（D0/B2e）不改进任何指标**：D0 航程更短（1265 vs 1427 km，
    DEM 竖切面本就更长）但按时率/产出与 M0 无统计差异——支撑「DEM 是
   建模贡献而非刷榜」的定位。
4. **贪心（B2/B2e）包围随机（B1）但被 DMDE 压制**：按时率 0.72–0.73 vs
   0.598 vs 0.770；奖励产出 0.87–0.88 vs 0.811 vs 0.898。
