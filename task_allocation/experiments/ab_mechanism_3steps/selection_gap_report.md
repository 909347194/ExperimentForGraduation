# 搜索口径 vs 交付口径：选择错配的量化诊断

> `ab_mechanism_3steps` 的补充探针（零侵入 monkeypatch，生产代码零改动）。
> 回答：DE 按 `f(S_eval(x))` 选出的精英，是不是 `f(S_final(x))` 下的最优？

## 1. 论断的代码坐实（比「映射不同」更严重）

**f 是同一个函数。** 搜索期 `evaluator.evaluate` 取 `problem.scalar_fitness(solution)`（`evaluator.py:199`），交付期 `stage_runner.py:346` / `:363` / `:400` / `:437` 逐次重算的也是同一个 `problem.scalar_fitness`。所以两式的差异**全部来自映射 S**，不是目标函数换了权重。

| | 搜索期 `S_eval(x)` | 交付期 `S_final(x)` |
|---|---|---|
| 入口 | `evaluator.evaluate(assignment)` | `build_solution(result.best_assignment)` |
| 代码 | `dmde_solver.py:219` → `evaluator.py:197` | `stage_runner.py:344` |
| 后续 | 无 | assignment polish `:354`、memetic 档案 `:370`、coverage_first `:388`、交付后成本 polish `:415` |
| 作用对象 | **每个候选个体** | **仅被选中的那一个** |

三点必须补上，用户的形式化还低估了问题：

1. **后处理不保序。** `S_final` 里的 polish 是 x 依赖的局部搜索，改进量 `Δ(x)=f_eval−f_final` 随 x 的局部结构变化。只要 Δ 不是常数，就能构造 `f_eval(x₁)<f_eval(x₂)` 但 `f_final(x₁)>f_final(x₂)` 的排序反转。且 DE 只在**一个**胜出个体上执行 polish —— 这是「先选后打磨」，与「先打磨后选」不等价。
2. **精英基因被替换，适应度却是「继承」而非重算（结构性风险）。** `dmde_solver.py:241-248`：Lamarckian 回写得到新基因 `re_encoded` 后，`re_encoded.fitness = child.fitness` 把**回写前基因的适应度**直接抄给新基因，再存入种群；下一代 `if child.fitness < population[i].fitness` 比较的就是这个继承值。其正确性**依赖回写不变式**（`evaluator.py:233-240` 的 Q2.1：写回后以 `temperature=0` 重解码，表型必须等于目标修复解）。但默认路径走 `_reencode_start_only`（`evaluator.py:267-273`），只改写起始通道、**巡游基因保留未修复原值**，Q2.1 的表型复核仅在 M2-1 开启时执行；回写异常还被 `except: pass` 静默吞掉（`dmde_solver.py:244-246`）。所以这是一个未加校验的假设，不是已证实的数值 bug。`stage_runner.py:314-320` 的注释已承认「交付解与当时被评价的解任务集/顺序/ETA 均可不同，两者适应度本不可比」。本探针实测最终精英的 `f(build_solution(best_assignment)) − best_fitness` 来检验其是否真的失准（见第 3 节 `陈旧适应度差`）。
3. **逐代贪心是路径依赖的。** 即使两口径完全同序，DE 也是逐代替换，`f_final` 意义下的好个体若在早期因 `f_eval` 略差被淘汰，就永远进不了种群，`argmin` 的候选集本身已被截断。

**argmin 相等的充分条件**：存在严格递增 `g` 使 `f_final = g ∘ f_eval`（特例：`Δ(x) ≡ 常数`）。交付后 polish 是逐点局部搜索，不满足该条件，除非所有候选恰好都落在同一局部最优盆地。

## 2. 实验设计

- 单周期纯几何随机 SRP（与三步实验同场景/同种子/同评价口径）。
- **重放时点（关键口径修复）**：`DMDESolver.solve` 刚返回时 `problem` / `evaluator` 仍是搜索期状态（实测同一基因重解码逐位复现），但 `horizon.run` 随后的交付期后处理会**原地改动** evaluator 的可变状态 —— d150 下若在 run 结束后重放，重解码漂移 −375.37、所有候选塌成同一个解，并列最优数与反转率全部失真。故在 `_on_solve` 内 `deepcopy(evaluator)` 取隔离副本，全部重放只在副本上做：既锁住搜索期口径，又不污染生产链。修复后 d0 / d150 的 `|f_eval − f_redecode|` 均为 0。
- hook `DMDESolver._evaluate` / `_evaluate_result` / `solve`，记录本次 run **每一个被评价过的基因** `assignment` 及 `f_eval`；按 assignment 去重。
- 对每个候选离线重放交付映射：D1 重解码（隔离校验，应与 `f_eval` 逐位相等）；D2 再叠加 `post_cost_polish`，按 `stage_runner` 同款四道门（执行集不减 / 硬违约不增 / excess 不增 / 航程严格下降）决定采纳，ε 取生产默认 `cost_polish_eps=1.0`（`stage_config.py:161`），与 `stage_runner.py:434` 逐位对齐。
- `refine=关`（关掉交付后成本优化总闸）时 D2 恒等于 D1，作为**隔离对照**：若错配仍存在，就来自重解码/基因替换而非 polish。
- 直接测两个 argmin：`x*_eval=argmin f_eval`、`x*_final=argmin f_final`，以及 `regret = f_final(x*_eval) − min_x f_final(x)`（现状「先选后打磨」vs 理论上限「先打磨后选」）。

## 4. 判定

**d0：两个 argmin 恰好重合，但序关系已被破坏**。regret=0.00，可排序反转率 **0.477**、Spearman **0.059**、`Δ(x)` 强依赖 x ⇒ `f_final=g∘f_eval` 不成立，两个 argmin **没有对齐保证**。regret 为 0 是因为平均 **34.3** 个候选被 polish 压到同一个 `f_final` 最小值（并列最优），DE 恰好选中其一，属退化巧合；选择价值从关闸时 **1984.81** 塌到 **154.72**。 **d150：两个 argmin 直接不重合**。top1 重合率 0.333、平均 regret **49.00**、DE 选中个体在交付口径下只排第 **2.7** —— DE 正确选出了 `f∘S_eval` 的最优，但它不是 `f∘S_final` 的最优，用户的形式化在数值上被直接坐实。 **总判定：用户论断成立。** 两种截止体制给出互补的失效形态：零迟到体制是「排序被压缩成大量并列最优、DE 的选择价值大幅塌缩」，强截止体制是「argmin 直接错位、产生可测 regret」；关掉交付后成本优化总闸后各体制都恢复完全对齐（Spearman=1、反转率 0），证明错配由交付后优化引入，而非重解码或随机性。根源是同一件事：后处理是 x 依赖的局部搜索，且只对胜出者执行一次，即 `select-then-polish ≠ polish-then-select`。

- **隔离校验**：`|f_eval − f_redecode|` 最大 **0**。该值为 0 ⇒ 同一基因重走 `build_solution` 逐位复现，错配**不是**重解码/随机性引入的，而是由交付后优化引入；关掉总闸后反转率应同步归零。
- **陈旧适应度**：最终精英的 `f(build_solution(best_assignment)) − best_fitness` 平均 **0.00**。本次为 0，说明回写不变式在最终精英上成立；但不代表中间代的继承适应度都正确（默认回写路径无 Q2.1 复核，异常被静默吞掉），仍是 P0 要补的校验点。

## 5. 与三步实验证据的勾连

- 2×2 消融交互项 **158.1**（进化效应 202.6 → 开精修后 44.5）：收益非可加，正是 `Δ(x)` 依赖 x 的宏观表现；若两口径同序，交互项应接近 0。
- 第一步精英冻结（冻结代占比 0.89、改进代数 0.2）：陈旧适应度使 `population[i].fitness` 与当前基因脱钩，贪婪选择天然倾向不替换 —— 这是「DE 选不动」的第二个独立解释，与「子代劣于初始精英」并存。
- 第三步 `prod` 基准定序边际 0：定序收益在解码期被提前消费，属于 `S_eval` 与 `S_final` 共享链路上被重复计入的部分。

## 6. 修复路线（按代价排序）

1. **P0 给继承适应度加校验（改动最小）**：`dmde_solver.py:241-243` 在 `child = re_encoded` 后，用 `fitness_evaluator.evaluate(re_encoded.assignment, ...)` 重算 `re_encoded.fitness`（有缓存，开销可控）并与继承值比对，不一致时计数/告警；同时把 `except: pass` 改为计数 + 日志。本次实测最终精英未失准，但默认回写路径无 Q2.1 复核、异常被静默吞掉，属于未加校验的结构性风险，补上即可消除。
2. **P1 让选择口径看见交付后处理**：把 polish 从「只对胜出者执行一次」改为「对候选集执行后再选」（memetic / 种群级局部搜索），或在选择阶段用 `f_final` 的廉价下界作代理。代价是评价次数上升，需重新标定预算。
3. **P2 结构性对齐**：把 `_consolidate` / `_best_order` / 跨机 relocate 从修复器剥离为显式优化模块（上一轮 P1），并给 `build_solution` 加 `DecisionTrace` 逐次标注 `hard|opt`，使 `S_eval` 与 `S_final` 的差异可审计、可按模块归因。
4. **论文口径**：不能写「DE 搜索并选择最优方案」；应写「DE 在 `f∘S_eval` 上做种群搜索并提名精英，交付解经重建与后处理定案；两口径排序一致性由本探针实测给出」，并把 `best_fitness` / `final_fitness` 并列报告。

## 7. 诚实口径

交付链 `stage_runner.py:344-438` 各步的**重放覆盖情况**（逐项声明，避免把「重放」误读成「完整交付链」）：

| 交付链步骤 | 本探针 | 说明 |
|---|---|---|
| `build_solution(best_assignment)` | 已覆盖 | D1 重解码，逐位复现 f_eval |
| `polish_assignment`（assignment 级局部搜索） | **未覆盖** | 每候选重放代价过高；生产只对胜出者执行一次 |
| memetic M1 档案择优 | 不适用 | 本实验 `polish_in_loop=False`，档案为空 |
| `coverage_first` 终态后处理 | 不适用 | `stage_config.py:96` 默认 `False` |
| `post_cost_polish`（交付后成本 polish） | 已覆盖 | D2，四道门 + ε=1.0 与生产一致 |

因此本文的 regret 是**下界**，不是完整错配幅度；「并列最优数」也可能因少一层打磨而与真实交付不同。所有在生产链里只作用于胜出者的模块，恰恰是造成「先选后打磨 ≠ 先打磨后选」的根源，本探针只量化了其中可重放的那一段。方向上是安全的：漏掉的 `polish_assignment` 是**又一次逐点局部搜索**，只会进一步压缩候选差异、增加并列，不会把已被打乱的序关系恢复成同序，故实测的反转率 / 并列最优数应理解为保守下界。
- 候选集 = 本次 run 实际被 DE 评价过的基因（含初始种群与 GMR 重建），不含从未采样到的基因；故 `min_x f_final` 是「同一搜索轨迹内」的上限，不是全局最优。
- **重放有效性门槛**：`redecode_gap_max = max|f_eval − f_redecode|` 必须为 0 才认为该 run 的重放锁定在搜索期口径；若非 0，该 run 的 反转率 / 并列最优 / regret 一律作废，不得纳入结论。本次修复后 12 组全为 0。
- 预算 pop/gens 低于生产口径（pop50×gen200），场景为纯几何 SRP，结论不外推到 DEM 有向代价与多周期滚动。
- 所有插桩在实验侧 monkeypatch，不改动生产代码，不影响 `pytest` 全量回归。
