# 第三步：定序 / 路径 polish / 任务归属搜索 —— 各自解决什么问题

**重点不是让每个模块都取得收益，而是确认每个模块解决什么问题。**

## 口径分离

- (A) 离线：用确定性轮询分配经 `build_solution` 构造一个**固定归属**基准方案，冻结其 task→uav、执行集、参与机，只改段内顺序；用真实 problem 评价四变体。四变体归属恒等（`frozen_ok`）是前提。**双基准**：`prod` 直接取 `build_solution` 输出（内部已消费定序），`reversed` 人为逆序劣化后再测，二者分开统计、不混平均。注：实测 `n_active_uav` 常为 1（覆盖优先 + 剩余航程充裕时修复链把全部任务并入单机航次），这本身就印证第一步「修复链坍缩归属维度」的判断——此时归属已无自由度，顺序/polish 是唯一还能优化的维度。
- (B)(C) 端到端：滚动交付量，`repair_only` → `assign_only`(仅 DE 归属搜索，冻结定序+关 polish) → `+定序` → `+polish`（生产组合）。
- 两者绝对量级不可比，分开读。

### 归因（Δ = 该基准的 base − 该变体，正 = 改善；双基准分开读）

- **prod / d0**：定序 Δ航程=0.00 / Δ迟到=0.00；路径 polish Δ航程=1261.59 / Δ迟到=0.00。
- **prod / d150**：定序 Δ航程=0.00 / Δ迟到=0.00；路径 polish Δ航程=637.84 / Δ迟到=462.75。
- **reversed / d0**：定序 Δ航程=0.00 / Δ迟到=0.00；路径 polish Δ航程=1692.32 / Δ迟到=0.00。
- **reversed / d150**：定序 Δ航程=-216.64 / Δ迟到=2628.56；路径 polish Δ航程=485.92 / Δ迟到=1459.13。

→ **`prod` 下定序边际≈0 是设计使然、不是算子失效**：生产交付方案的顺序本就是定序算子的输出，再调一次自然无增量；d0 零迟到时 `_best_order` 还会因 `reorder_range_optimize=False` 早退返回原序。
**只有 `reversed` 才测定序算子的能力上界**：人为逆序后，d150 下定序显著降迟到（表中 Δ迟到 为正）却**同时增加航程**（Δ航程 为负）——这是 `_best_order` 判据 `(迟到数, 迟到量, 航程)` 字典序优先时间窗的直接体现，说明定序是「以几何航程换时间窗合规」；d0 零迟到体制仍早退。
路径 polish 恰好相反：两种基准、两档截止下都稳定降航程（Δ航程 为正），且因几何变短顺带降迟到，四道门保证执行集 / 参与机 / 覆盖 / 硬违约不变。

**结论：定序与路径 polish 作用于不同、且在有截止压力时相互冲突的目标维度**——定序以航程换迟到、polish 只压航程冗余；两者虽都改「段内顺序」但不可互替，`order+polish` 叠加后在 d150 下同时取得最低迟到与显著压低的航程，证明互补而非冗余。且定序收益已在生产链里被提前消费，不应在「交付后优化」中重复计入。
（本实验重点在确认各模块解决什么问题，不以「每个模块都必须取得收益」为判据。）

### 每个模块解决什么问题（归因表）

| 模块 | 主战场 | 证据方向 |
|---|---|---|
| 任务归属搜索（DE） | 哪个任务给哪架机的组合分配 | 只在单周期高负载（60:1 类）显出航程/覆盖改进；易场景被修复链一次给到近优而冗余 |
| 定序 `_best_order` | 时间窗 / 迟到 | 有截止压力时降迟到；零迟到体制早退、边际近零 |
| 路径 polish（2-opt/Or-opt） | 几何航程冗余 | 各体制稳定压航程，四道门保证不牺牲执行集/迟到/硬违约 |
| 修复链（地板） | 可行性 / 覆盖 | 归属改写、补装、航程闸，所有模块的共同前提 |
