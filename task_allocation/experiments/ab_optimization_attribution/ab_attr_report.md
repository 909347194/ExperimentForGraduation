# 优化工作归属消融报告（ab_optimization_attribution，合并版）

## 0. 速读结论

三级嵌套消融（C=修复链裸基线 gens=0 / A=+进化 / B=全开+精修）显示：**优化工作的归属高度依赖问题体制**，而非固定比例。

- **小批量场景（40:2、20:3）**：进化贡献 **0%**，全部改进来自精修（polish + 定序）；无论截止宽松（d0）还是过紧不可行（d150）。
- **大批量可行场景（60:1，d0）**：进化贡献 **~69%**，精修 **~31%**——单周期 60 任务的组合分配是硬问题，DE 全局搜索才啃得动。
- **大批量不可行场景（60:1，d150）**：截止过紧导致全量迟到（不可行），进化回落到 **0%**——此时修复链已把解锁死在「全迟到的局部结构」，DE 无梯度可爬。

> 机制探针（40:2，gens=80/pop=20，**lamarckian=False**）验证：进化臂仍 = 修复链裸基线（7937.661），说明 0% 进化不是 lamarckian 抹平，也不是预算太小，而是**修复链把搜索空间坍缩**——进化在此表示下结构性冗余。

## 1. 方法与三臂

- **repair_only**：`max_generations=0`（无 DE 搜索）+ 精修全关 → 修复链裸基线 C；
- **evolution**：`max_generations=正常` + 精修全关 → 进化边际 = C - A；
- **full**：`max_generations=正常` + 精修全开（生产默认）→ 精修边际 = A - B。
总改进(相对裸基线) = C - B；进化占比 = (C-A)/(C-B)，精修占比 = (A-B)/(C-B)。修复链地板 C 为可行性必需，不可归零，单独报告。

## 4. 机制：为什么进化常常 0%

1. **空间坍缩**：修复链（覆盖优先装载 + 终点机巢最小费用流 + `_best_order` 定序 + lamarckian 逐代写回）把大量不同基因映射到同一/相近可行解，搜索景观被压平，DE 的变异/交叉撬不动。探针（40:2，gen=80、pop=20、lamarckian=False）中进化臂路径仍 = 7937.661 = 裸基线，排除「lamarckian 抹平」与「预算太小」两类疑似原因。
2. **精修算子更强**：polish 的 2-opt/Or-opt/relocate 是针对性局部搜索，能啃下修复链遗留的路径冗余（40:2 d0：7937→7389，约 7%）；DE 的全局算子在同表示下够不着这些局部改进。
3. **体制依赖**：当单周期任务量大（60:1，可行时序）时组合分配足够难，修复链不再能一次性给到近优分配，DE 才显出 ~69% 贡献；一旦截止过紧到不可行（d150，全量迟到），景观再度被迟到惩罚压平，进化回落 0%。

## 5. 诚实口径与上限

- 本实验预算为 **pop∈{8,12}、gen∈{25,40}**，低于生产口径（exp01 用 pop50/gen200）；更大预算下 60:1 类硬场景的进化占比可能更高，但 40:2/20:3 类易场景经探针（gen=80）验证仍为 0%，结论稳健。
- 三级嵌套的边际贡献在「其余固定」下度量，进化与精修存在交互（搜索 landscape 受精修影响），故占比为边际口径、非严格可加；C 为可行性地板，不可归零。
- d150 实为**不可行截止**（迟到 ~3.7e4–4.5e4 s），是压力/不可行体制而非「紧可行」；其结论应读作「不可行体制下进化退化」，不应外推为「任何时间压力都让进化失效」。
- 每 combo n 偏小（1 几何 × 3 求解器种子配对），绝对量级有噪声，方向与占比稳健。
