## 0. 执行摘要

1. **exp01 复现了既有的生产口径基线**：3 个 seed 全部 60/60 完成、废飞 0、淘汰 0、物理不可达 0、期末残留 0；按时率 **91.7±4.4%**、奖励产出率 **0.978±0.016**、总航程 **1693±64 km**、求解 **571±21 s**。与 2026-10-20 记录的「P（生产+polish）」格（91.7±3.6% / 1693.0 km / ~595~660 s）逐位一致 —— 口径未漂移。
2. **exp02 确认「选择名额必须接 cap(t)，候选名额只需 ≥ 选择数」**：α 驱动的 `quota_*` 在 N=50→100 时 F1 从 133→131 **完全饱和**（n_sel 恒 16），而全量上界从 292.7→356.5 持续增长；能力驱动 `cap_x1` 在 N=100 保住全量收益的 **83.4%**，耗时只有 **12.9%（7.75×）**。同时压缩把求解成本与 N 解耦：n_sel 固定 16 时，N=50 与 N=100 的端到端耗时 **27.2 s vs 26.4 s**（基本不变）。
3. **exp05 首次给出「优于谁」的量化证据**，但结论是**分层**的，不是全面碾压：
   - 本文方法 M0 在**完成率与奖励产出**上最优（0.997 / 0.977），按时率 0.916；
   - 贪心 B2 **确实更省**：单位完成航程 25.22 km vs M0 27.97 km（**M0 贵 +10.9%**），但按时率只有 0.720（**−19.6 pp**）、奖励产出 0.877（−10.0 pp）；
   - VRPTW B3 是唯一**零迟到**（1.000）的臂，代价是完成率掉到 0.953；
   - 随机 B1 作为下界，单位完成航程 +46.6%、按时率 0.582。
4. **对第 2 问的判定已可给出**：DMDE「成本不如贪心」**不是完成率权衡的假象，而是真实的成本差距**（等完成率下贵 +10.9%）。但它换来的是 +19.6 pp 按时率与 +10.0 pp 奖励产出。**「加代数能否追平成本」的先验应大幅下调**：实测 `fitness_weights` 显示成本项 λ·path ≈ 48，而完成项 m·F1 ≈ 2.7e7，**成本项只有完成项的 1/5.6e5** —— 成本在当前权重下是纯 tie-break，根本不进入权衡。所以这是**目标结构问题，不是搜索预算问题**（详见 §4）。
5. **距离模型消融给出独立证据**：欧氏臂 D0 的账面奖励产出（0.981）与 M0（0.977）几乎相同，但**实际按时率 0.893 < 0.916**、航程少 6.1% —— 欧氏低估航程会让排程「以为赶得上」，是 DEM 三维代价必要性的直接证据。

### 1.2 恒等式与正确性审计

`arrived = done + unreach + elim + remain` → **60 = 60 + 0 + 0 + 0**，三个 seed 全部闭合。正确性审计 **23/24 PASS，1 项 WARN**（D 组「latest 翻转在方向不确定带内」，已知低危口径差异，残差 p50=0.0 s / max=22.8 s）。

### 1.3 需要注意的一处口径效应（非 bug，但跨 seed 比较时会被误读）

seed 44 的 `correct_exec_rate` = **0.548**，而它的 `on_time_rate` = **0.900**。原因不是错误，是两个统计量的定义不同：

- `on_time_rate` = 池化口径 `(总执行 − 迟到 − 废飞) / 总执行` = (60−6)/60 = 0.900；
- `correct_exec_rate` = **逐周期按时率的未加权均值**（空转周期不计入）。

seed 44 的周期结构与 42/43 不同：

| seed | 周期 1 | 2 | 3 | 4 | 5 | 6 | 7 | 总周期 |
|---|---|---|---|---|---|---|---|---|
| 42 | 20 (迟2) | 20 (迟3) | 20 (迟2) | 0 | 0 | 0 | 0 | 7 |
| 43 | 20 (迟0) | 20 (迟2) | 20 (迟0) | 0 | 0 | 0 | 0 | 7 |
| 44 | 20 (迟1) | 18 (迟2) | 18 (迟0) | **1 (迟1)** | **1 (迟1)** | **1 (迟1)** | **1 (迟0)** | 11 |

seed 44 有 4 个任务在周期 4–7 **逐个**被交付且几乎全迟到，把这 4 个「1 个任务、1 个迟到」的周期（correct=0.0）与 3 个大周期等权平均，就把 0.900 拉到 0.548。

**结论**：seed 44 的结构性差异是真实的（拖尾 4 周期、总周期 11 vs 7、每活跃周期吞吐 8.57 vs 20.00），但 `correct_exec_rate` 这个**未加权**统计量把它放大成了看似「正确率腰斩」。论文里报按时率应统一用**池化口径** `on_time_rate`；若要用逐周期均值，须明确标注为「每周期正确率的均值」并改为按执行数加权。

### 2.3 三条可写进论文的结论

1. **压缩把求解成本与 N 解耦。** n_sel 固定为 16 的 `quota_a2.5` 在 N=50 与 N=100 下端到端耗时 **27.2 s vs 26.4 s**（差 3%），F1 也基本不变（133.2 vs 131.0）。而不压缩的 `full_baseline` 从 165.6 s 涨到 1100.7 s（**6.6×**，N 只翻一倍，明显超线性）。这是第一阶段存在的**根本理由**。
2. **α 名额（quota_*）不可规模化的直接证据。** `quota_a2.5` / `quota_a5` 的 n_sel 恒为 16/16，与 N 无关；于是 N=50→100 时 F1 从 133.0 略降到 131.0（甚至 `quota_a5` 从 129.1 降到 120.1），而全量上界从 292.7 涨到 356.5。**α 名额把系统的吞吐上限钉死在机数倍率上，规模再大也吃不到**。这直接支撑「选择数必须接 cap(t)（mode=primary），候选名额只需 ≥ 选择数」的口径修订。
3. **能力驱动标定是最优点，但 N 越大代价越明显。** `cap_x1` 在 N=50 用 87.4% 的耗时拿 93.5% 的收益（加速比仅 1.14×，**压缩收益不划算**）；到 N=100 用 12.9% 的耗时拿 83.4% 的收益（**7.75×，非常划算**）。即：压缩的价值随 N 单调上升，N=50 附近是变点。

**N=10 一格无效**：所有 variant 的 n_cand 都被任务总数 N=10 截断（α·K=20 > 10），五项逐位相同（F1 均 51.2），压缩机制完全未被触发。论文里可保留这格作「机制未激活」的说明，但不能拿它论证压缩效果。

### 3.4 怎么解读（诚实版本）

**不是「全面碾压」，而是三个不同的 Pareto 点：**

- **M0（本文方法）**：完成率与奖励产出率最高，按时率次高。它是「既不牺牲完成、也不牺牲太多准时性」的选择。
- **B3（VRPTW）**：唯一零迟到（1.000±0.000，平均迟到 0 s）。代价是完成率 0.953 —— 硬时间窗让它**宁可不做也不迟到**。这是「准时性优先」的极端点。
- **B2 / B2e（贪心）**：成本最优（−9.8% / −10.1%），完成率不输，但按时率只有 0.72 / 0.73，奖励产出 0.88 / 0.87。它是「成本优先、牺牲准时性」的点。
- **B1（随机）**：下界，航程 +46.6%、按时率 0.582 —— 证明这个域里引擎差异确实是有效信号，不是噪声。

**写作建议**：论文主表应同时报（完成率, 按时率, 航程）三列并明确「本文方法在奖励产出与完成率上最优、在成本上高出贪心约 10%，该差距换取 +19.6 pp 按时率与 +10.0 pp 奖励产出」。只报航程一列会显得不如贪心；只报完成率会掩盖成本代价。

### 3.5 距离模型的独立证据（D0 vs M0）

D0 与 M0 唯一差异是代价函数（欧氏 vs DEM 三维）。结果：

- 账面奖励产出 D0 0.981 略**高**于 M0 0.977；
- 但实际按时率 D0 0.893 **低**于 M0 0.916（−2.3 pp）；
- 航程 D0 1575 km vs M0 1672 km（**欧氏低估 6.1%**）。

机制解释清楚：欧氏低估真实三维航程 → 排程器「以为」赶得上截止期 → 账面收益看起来不差，执行时却真的迟到。这是 DEM 三维代价必要性的**直接、可写进论文**的证据，也顺带说明为什么「奖励产出」单列不足以评价代价模型。

## 4. 对第 2 问的判定：DMDE 的次目标（成本）搜索，100 代 vs 500 代 vs 贪心

原假设：「DMDE 100 代不如贪心，可能是因为代数不够，成本作为次目标没被充分搜索。」

**现在有数据了，判定如下：**

### 4.1 先排除「完成率权衡假象」这个解释 —— 差距是真实的

之前的推测是：贪心成本低是因为它完成得少，所以是假象。数据否定了这一点：

- M0 完成 59.8 / 60，B2 完成 60.0 / 60 —— **完成数基本相同**；
- 单位完成航程 M0 **27.97 km** vs B2 **25.22 km** → M0 **贵 +10.9%**。

**所以成本差距是真差距，不是完成率权衡的产物。** 这一点必须先写清楚，否则答辩会被追问。

### 4.2 但这不是「代数不够」—— 是目标结构里 λ 太小

机制上（适应度 `f = … − m·F1_eff + … + λ·path + …`）。我原本以为 λ·path 只是「比完成项小一两个量级」，**实测比这极端得多**。直接从 exp01 seed 42 周期 1 落盘的 `fitness_weights` 快照读：

| 项 | 实测值 |
|---|---|
| `m`（完成项系数） | 232,916.87 |
| `λ`（成本项系数） | 1.0e-4 |
| `F1`（该周期收益，已含迟到折减） | 116.50 |
| `path`（该周期纯路径） | 477,696.2 m |
| `L_tot`（该周期迟到合计） | 1,849.4 s |
| `m·F1` | ≈ 2.7135e7 |
| `λ·path` | ≈ **47.8** |
| `w_late·L_tot`（w_late=0.01/s） | ≈ **18.5** |

**成本项 ≈ 完成项的 1/5.7e5。** 换成直观说法：放弃一个奖励为 1 的任务，适应度代价是 2.3e5 —— 相当于 **23 亿米**航程。也就是说：

- 在当前权重下，成本**绝对不可能**与完成做任何权衡，它只在「完成集完全相同」的解之间充当 tie-break；
- DMDE 的代数 100% 花在爬完成上，成本是被顺带精修的；
- 而 B2 是**直接以收益/代价比为唯一准则的构造式**，从一开始就把成本当主目标。

**这是结构性的差异，不是预算差异。** 因此：

- **单纯加代数（100→500）几乎注定无效**：成本项只有完成项的 1/5.6e5，搜索对 path 的选择压力比 F1 弱五个数量级以上。500 代只会把「已经收敛的完成集」反复重排，能压掉的成本受限于 tie-break 被触发的频率，量级上难以追平 10% 的结构性差距；
- **真正有效的干预是改目标结构，不是加预算**：要么**重标 λ**（让 λ·path 与单个任务的收益当量可比），要么**在已完成集内加显式成本 polish**（2-opt / 跨机 relocate），这类算子绕过适应度梯度直接改路径。

> **一处需要复核的口径冲突（写论文前必须解决）**：先前笔记记的「覆盖优先边界 λ_crit ≈ 1.4e-5」，暗示 λ 超过 1.4e-5 就会开始牺牲覆盖；但本次实测 λ=1e-4（已是 λ_crit 的 7 倍）时，成本项仍只有完成项的 1/5.6e5，完全没有牺牲覆盖。两者必然有一个用了不同的归一化口径（前者可能按「单位航程 vs 单位收益」而非「λ·path vs m·F1」）。**在 λ 敏感性扫描做出来之前，不要在论文里引用任何一个 λ_crit 数值。**

### 4.3 建议的验证顺序（都已就绪，不用改 YAML）

1. **exp05 500 代对照**（最直接）：
   `python run.py --arms M0 --set solver.max_iter=500 --set experiment.output_dir=results_dmde500 --seeds 42-46`
   对比 `results/M0`（100 代）vs `results_dmde500/M0`（500 代）vs `results/B2`（贪心）的 `total_path_m / completion_rate / on_time_rate`。
   - 若 500 代把单位完成航程从 27.97 压到 ≲25.2 → 是代数问题，加代数即可；
   - 若仍停在 27 上下 → **确认为目标结构问题**，应转去做 λ 重标，不要再烧代数。
2. **exp02 N=100 `--set solver.max_generations=500`**：有真实路由空间的域，验「有路由空间时多代能否精修成本」。
3. **exp01 `--max-iter 500`**：**先验表明不会有质量增益**（fixed-60 是无路由空间域，2026-10-14 已实测 500 代只更慢：315 s vs 1444 s，零质量增益）。若时间紧可跳过，或明确标注为「敏感性对照」，不作为主口径。

### 4.4 一个要提前想好的答辩问题

「你说你的方法更好，可它比贪心多飞 10%。」——准备好的回答是：

> 这 10% 不是浪费，是买来的：它换来 +19.6 pp 按时率与 +10.0 pp 奖励产出。贪心之所以便宜，是因为它把任务塞进便宜但会迟到的航次里；在本问题的评价口径下（迟到按 L/W 折减有效奖励，但不计废飞），这笔交易是划算的 —— 奖励产出率 0.977 vs 0.877。若决策者权重转向纯成本，λ 重标即可把工作点移向 B2，这是我们方法的可调旋钮，而贪心没有这个旋钮（它只能给一个点）。
