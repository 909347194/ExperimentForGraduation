# 算子契约（Operator Contracts）

> 本文档是第二阶段 `repair_chain` 解码/修复算子的**规范**，不是事后总结。
> 任何对算子的新增、改名或语义调整，都必须在同一次提交里同步本表；
> 与本表冲突的代码注释以本表为准。
>
> 适用口径（生产配置）：`decode_mode=repair_chain`、`coverage_gate=true`、
> `coverage_first=false`、`prune_unprofitable=false`、`prune_zero_reward=false`。
> 非生产路径见文末「消融与关闭分支」。

---

## 1. 全局不变量

下列不变量对**整条管线的输出**成立。单个算子可以暂时不满足全局最优，但
不得破坏其标注「保持」的不变量；下游算子负责把暂时违反的状态修复回来。

| 编号 | 不变量 | 含义 |
|---|---|---|
| I1 | 一任务一机 | 每个任务至多出现在一条航次中、且在该航次内至多一次（`y_j ∈ {0,1}`）。 |
| I2 | 可达即执行 | 对硬约束下存在可行落点的任务，必须交付，不得因经济性被丢弃；仅当所有落点都不可行时才 `y_j=0`（证明性暂缓）。 |
| I3 | 硬约束可行 | 交付解满足航程、续航、时序、同步、机巢容量、终点可达等全部**硬约束**。 |
| I4 | 修复不制造新违约 | 任一算子的输出相对其输入，不新增硬违约；只允许把不可行状态向可行方向移动。 |
| I5 | 确定性 | 所有遍历按 id 升序、无随机分支，评估缓存可安全复用。 |

术语口径：**硬约束**违反即判物理不可行（I3）；**时间窗**（迟到）是软约束，
迟到计完成、经 `w_late·L_tot` 单一计价，不触发 I2 的暂缓。

## 2. 生产管线（固定顺序）

`build_solution` 按下列顺序调用，顺序本身是契约的一部分（联合收敛依赖它）：

```
1. 联合收敛循环（上限 6 轮，每轮）：
     _consolidate → _repair_range → _choose_end_nests
2. _complete_coverage          # 覆盖补全（可达即执行）
3. _reorder_for_deadlines      # 时间窗重排（不改任务集）
4. _repair_sequence            # 同链时序归位（硬约束）
5. _repair_range               # 航程闸
6. _choose_end_nests           # 终点巢重配（容量精确解）
7. _repair_range               # 交付前终闸
8. repair_coverage             # 覆盖门禁：能救必救（上限 8 轮）
9. 仅在仍有逆序时 _sequence_fix
10. _assemble                  # 装配 AllocationSolution
```

`_reflow_task`、`_sequence_fix`、`_best_order` 是被上述算子调用的原语，
不单独占据管线位置。

## 3. 逐算子契约

### 3.1 `_consolidate`（合并修复）

| 栏 | 内容 |
|---|---|
| 角色 | 任务少时把航次并入更少的机，使闲置在解码端可表达。 |
| 保持 | I1、I2、I3、I4；不删除任何任务。 |
| 可动 | 整航次迁移：把供体任务逐个最优插入受体航次；供体航次置空表示该 UAV 本轮闲置。 |
| 接受条件 | 仅当「起始腿 + 任务链 + 返航腿」总代价严格下降，**且**合并后航次不超受体航程预算（结构性航程门）才合并。 |

### 3.2 `_repair_range`（航程修复）

| 栏 | 内容 |
|---|---|
| 角色 | 把超航程航次拉回剩余航程内。 |
| 保持 | I1、I3、I4；I2（移除的任务必须先走 reflow，不直接吞）。 |
| 可动 | 逐个移除「移除后节省最多」的任务，并对每个被移除任务调用 `_reflow_task` 改派。 |
| 接受条件 | 循环直至每条航次全航程 ≤ 该机剩余航程；被移除任务全部落点不可行时才允许其证明性暂缓。 |

### 3.3 `_choose_end_nests`（终点机巢分配）

| 栏 | 内容 |
|---|---|
| 角色 | 为各航次精确分配终点机巢。 |
| 保持 | I1、I2、I3；不改变任务集与航次内顺序。 |
| 可动 | 仅改 `end_nests`（`z_ub`）。 |
| 接受条件 | 内层最小费用流（MCF）在机巢容量约束下取费用最小的可行分配；无可行巢的航次不被强行指派。 |

### 3.4 `_complete_coverage`（覆盖补全）

| 栏 | 内容 |
|---|---|
| 角色 | 主动补全「物理可达却没被编入航次」的任务。 |
| 保持 | I1、I2、I3、I4。 |
| 可动 | 对每个未分配任务，经 `_reflow_task` 插入现有航次或拉闲置机开班。 |
| 接受条件 | 硬约束可行即装（存在量化）；时间窗是软约束，不否决「飞得到但迟到」的任务；硬约束不可达才保持 `y_j=0`。 |

### 3.5 `_reorder_for_deadlines`（时间窗重排）

| 栏 | 内容 |
|---|---|
| 角色 | 在不丢任务的前提下减少时间窗违约。 |
| 保持 | I1、I2、I3；**任务集不变**。 |
| 可动 | 仅调航次内访问顺序。 |
| 接受条件 | 候选集为常数个（原序/EDD/earliest/slack/NN），按 `(迟到任务数, 迟到总量, 航程)` 元组字典序取最优；超剩余航程的候选剔除。 |

### 3.6 `_repair_sequence`（时序修复）

| 栏 | 内容 |
|---|---|
| 角色 | 同链任务按 `sequence_order` 升序归位（硬约束）。 |
| 保持 | I1、I2、I3；**任务集不变**。 |
| 可动 | 仅调序：链内成员按序号升序填回原链占据的位置槽，链外任务不动。 |
| 接受条件 | 仅当 `constraints.sequence=true` 且存在逆序时动作；无逆序恒等返回。 |

### 3.7 `repair_coverage`（覆盖门禁，来自 `coverage_gate`）

| 栏 | 内容 |
|---|---|
| 角色 | 终态对未交付任务做一阶检验，能救必救，使 `voluntary_skip` 构造归零。 |
| 保持 | I1、I2、I3、I4。 |
| 可动 | 插入现有航次 / 空闲机开班；`gate_stats` 记录 shortfall 与轮数。 |
| 接受条件 | 迭代至无新可救任务（不动点）或达到 `coverage_gate_max_rounds`（默认 8）；硬约束不可达的 shortfall 保留并如实上报。 |

### 3.8 原语 `_reflow_task`（改派救援）

| 栏 | 内容 |
|---|---|
| 保持 | I1、I3、I4；全程确定性（I5）。 |
| 可动 | 按「插入现有航次 → 闲置机开班（全机队口径）→ 换机腾位（仅 `active_completion`）」依次尝试。 |
| 接受条件 | 任一落点满足硬约束即返回 `True`；全部不可行返回 `False`（调用方据此记证明性暂缓）。被动救援不启用换机、保持最小干预。 |

## 4. 不动点语义与收敛实测

### 4.1 为什么需要不动点

单个算子**不幂等**：`_consolidate` 改变机巢归属后，`_repair_range` 面对的
航次结构随之变化，`_choose_end_nests` 又可能改近终点巢。因此正确性论证
对**整体收敛后的解**做出，而不是对单个算子。

### 4.2 可行性与收敛性分离（关键论证）

- **可行性（I3）是逐算子单调保证的**：每个算子按 I4 不制造新违约，
  因此无论循环在何处终止，输出都满足硬约束。
- **成本收敛是尽力而为的**：循环截断只影响「是否还能进一步降本」，
  不影响可行性。这使硬上限可以安全存在。

### 4.3 「6 轮」的出处

`for _ in range(6)` 的 6 是联合收敛循环的**硬上限**。在生产配置
（seed 42，18 804 次 `build_solution`）下实测：

| 实际轮数 | 次数 | 占比 |
|---|---|---|
| 2 | 5 295 | 28.2% |
| 3 | 7 752 | 41.2% |
| 4 | 3 199 | 17.0% |
| 5 | 1 297 | 6.9% |
| 6（触顶截断，未到不动点） | 1 261 | 6.7% |

- 均值 3.23 轮；93.3% 的评估在 ≤5 轮达到不动点。
- 6.7% 触顶截断：按 4.2，截断解仍满足 I3，仅未穷尽降本机会。
- 论文表述应写「迭代至不动点或硬上限 6 轮；实测均值 3.2 轮、6.7% 触顶」，
  不应无条件声称「全部修到不动点」。

## 5. 消融与关闭分支

下列算子**不在生产路径**，仅用于消融对照或压力测试。它们与生产算子物理隔离
（独立模块 / 独立门控），阅读主链路时无需确认其开关。

| 算子 | 触发条件 | 用途 |
|---|---|---|
| `_prune`（经济性剔除） | `prune_unprofitable ∧ ¬coverage_first` | 选择性 `y_j=0` 的消融臂；生产 `prune_unprofitable=false`。 |
| `_prune_zero_reward`（零奖励剔除） | `prune_zero_reward=true` 且折减窗开启 | 零奖励任务压力场；生产关闭。 |
| `_load_coverage_fixed_point`（覆盖优先装载） | `coverage_first=true` | 覆盖优先解码两段式对照；生产关闭。 |
| `_build_constructive`（构造式解码） | `decode_mode=constructive` | 解码方式对照臂；生产为 `repair_chain`。 |
| `_best_order` 候选集（`order_candidate_mode=neutral`） | `order_candidate_mode="neutral"` | 基因序边际消融（ab_order_marginal）：**基因原序不入候选**，一律走一般锦标赛（edd/earliest/slack/nn）裁决，零迟到早退仅对 gene 臂生效。若 neutral 臂在零迟到走快返回，等于基因序泄漏回对照臂、配对对照失真（2026-11-05 审查 P1）。生产 `order_candidate_mode="gene"`。 |

## 6. 维护规则

1. 改算子先确认它「保持」的不变量，改动后这些不变量必须仍成立。
2. 新增可关闭算子默认 **off**，并在第 5 节登记，不得裸挂主链路。
3. 字段/算子命名必须与实际语义一致；保留旧名只能通过显式
   `DeprecationWarning` 垫片，且在第 5 节或本文注明退场计划。
4. 收敛轮数等经验上限若调整，需重新跑第 4.3 的实测并更新数字。
