## 4. 十项关键判定（展开）

**F1（✅ 强项）算子层可放心宣称"沿用"。** CR / F / 混合差分 / GMR 四个算子的公式、判据方向（`rand ≤ CR`）、边界（首代 CR=1、末代 CR=0）与 [M17] 逐位一致，且 `tests/test_operators_fidelity.py` 以抛异常方式锁死（该文件历史上曾出现"只打印不抛"导致 4 个测试空转，已修）。这是本项目对文献最扎实的一处。

**F2（⚠️ 中风险）Rule 1 的随机化是"改进"而非"复现"，但缺独立消融。** [M17] 式(15) 是确定性 argmin；我们的生产路径是温度退火 softmax top-k（`top_k = 1 + 7·temp`，`temp = 1 − gen/S`）。它同时承担了"多样性来源"这一角色，而同一时间还有 CR 退火在承担探索/开发调度——**两条退火曲线叠在一起，任一结论都无法单独归因**。建议：加一个 `inverse_match=greedy|annealed` 开关（默认不改），在 exp04 跑单列消融；论文里把"最近邻匹配 + 温度自适应"作为一个**可隔离的改进点**写，而不是混在"本章在最近邻匹配上引入温度自适应机制……并在匹配后辅以扰动"这一句里一笔带过。

**F3（⚠️ 中风险）匹配后扰动与温度自适应的归因纠缠。** `_perturb_genes`（概率 0.4·T）与 `_perturb_srp_tour`（0.5·T，swap/insert/reverse）都挂在同一个温度上。若不隔离，答辩时"你的探索性到底来自 CR、softmax 还是扰动？"无法回答。与 F2 合并成一个消融矩阵最省事：`{贪心匹配, 退火匹配} × {无扰动, 有扰动}`。

**F4（❗ 必须修）`alpha`/`beta` 是死参数，且取值与我们的模型分支不符。** [M17] 式(1) 的 a/b 在 N<M 分支取 **a=1.5, b=1**，而 `DMDEConfig` 默认写成 2.5 / 1.5（那是 N≥M 分支的值）。虽然它们从未被读取（`solve()` 全程未用），但一旦有人在论文里写"沿用其目标函数缩放因子"，就是双重错误。建议：要么删除这两个字段，要么在注释里明确"本文目标函数已替换，此二字段为历史遗留、不参与计算"。

**F5（⚠️）`w_time`（[M17] 的负载均衡项）默认关闭。** `exp01/config.yaml:192` 为 0.0。若论文写"沿用 [M17] 的双目标（代价 + 最坏机时间）"，与实际不符；若确实关闭，就写"本文现阶段双目标退化为航程单目标 + 迟到软计价，最坏机时间项作为可选扩展（权重可配置，默认 0）"。

**F6（⚠️）Twait / 同时到达未实现。** [M17] 把约束(9) 替换为 `Twait` 异步初始等待，这是它的一个自述贡献点（Sec.1 末）。我们不需要它（无协同打击/同时到达语义），但"沿用其约束体系"这类笼统表述要避免；建议写成"沿用其约束分类（分配关系、时序、时间窗、航程、续航），未引入其协同同时到达与异步初始等待约束，因本文任务为单点独立执行"。

**F7（❗ 必须修）垂直切面代价的引用链。** `cost/vertical_section.py:5` 写"论文思路（赵明等）"。[M17] 自己说的是"**In [40], we have introduced … estimated the flight path cost by using the vertical section between a UAV and a target**"——[40] = Zhao M.S., … (2012) 自动化学报 38(12):2038–2048。因此垂直切面的**原始出处是 [40]，[M17] 只是沿用**。若论文只引 [M17]，属于二手引用；正确做法是**两篇并引**（[M17] 作为统一建模与 DMDE 的出处，[40] 作为垂直切面航程估计的出处）。【审读：此条写入论文前须再核 [40] 题录。】

**F8（❗ 必须修）config 注释与取值不自洽。** `exp01/config.yaml:330-340` 的注释写"max_generations：500（2026-10-14 由 100 上调，依据 Ming et al. 2017 标定）"，但取值是 `max_iter: 100`，且注释未纳入 2026-10-21 的反向结论（T9 案例显示 100 代占优 500 代，主口径定为 100 代）。**建议把注释改写为现状口径**：主口径 100 代（依据 T9 编码顺序人为依赖的 miss 诊断与 100/500 代对照），500 代为敏感性上界（依据 [M17] Fig.10 自述约 150 代收敛 + 实测 path 485→381 km 的余量）。注释与取值不一致在答辩/复核时是硬伤。


**F9（⚠️）实验协议差异需明确声明"非复现"。** 100 代 vs 1000 代、3 seed vs 10~20 次、无 PMXDE/SortDE/GA 对照。特别是：**CR 与温度的调度都以 `S`（总代数）为分母**，`S` 从 1000 改到 100 会整体压缩探索预算（`config.yaml` 注释已算出：随机匹配预算 0.9×Gen，100 代时仅 90 代 vs 原文 900 代）。这不是"参数微调"，是**搜索预算的量级变化**，必须在论文里作为标定项显式给出，并给出 100/500 代的对照证据（已有）。

**F10（⚠️）`baselines/README.md` 的对照算法清单超出实现。** README 列了 PMX-DE / Sort-DE / GA，注册表里只有 random / greedy / vrptw。要么补实现（这三个都是 [M17] 的直接对照，实现成本不高、且能让"与 [M17] 同协议对比"成立），要么把 README 改成"规划中"。【审读：补 PMXDE 时要注意 `README.md` 的硬性约定——不得在 baseline 内复制一份 DMDE 编码实现，须从 `methods/muas` 导入。】

**F11（✅ 可用的立论点）与 [L26] 的分层是"同构、反向"。** [L26] 是**外层精确**（扩展匈牙利 + 对偶热启动）+ **内层元启发**（SE-ABC 三维航迹）；我们是**外层元启发**（DMDE 搜归属与顺序）+ **内层精确**（终点机巢最小费用流，条件全局最优）。这一点可以直接写进第 3 章的定位段：本文的分层不是"先分配后规划"的单向解耦，而是**外层把组合维度交给搜索、内层把可精确求解的运输子问题交给精确算法**，且内层结果（返航代价）完整回到外层适应度（"完整成本评价原则"，`Chapter3_README.md:665-673`），避免了 [L26] 被本项目精读报告点名的"闭环单向下行"缺陷（其 C4）。

**F12（⚠️）与 [L26] 仍不可比。** 其精读报告已列的 C1–C4 硬伤（分式目标 `max B/C` 被丢掉、零成本虚列退化、一对一匹配与"多机协作"声称冲突、`c_ij` 未定义）与 C5/C6（无航程硬约束、无截止时刻、无任务到达流）决定了：**它的数字（−15%/−23%/−25%）不可作为我们的对标刻度线**。本轮审查确认方法层面亦然——我们没有任何组件来自 [L26]（SE-ABC、扩展匈牙利均未采用），它只能作为"相关工作 + 局限立论"出现。

## 7. 可直接使用的措辞草稿（**引用前须核对原文字面**）

> 本文以 Zhao Ming 等（2017）提出的离散映射差分进化（DMDE）为算子基础。在**表示层**，沿用其统一三元组基因编码与"以航程代价为媒介的离散—连续映射—逆映射"机制，并沿用其三条逆映射匹配规则（最近邻匹配、唯一性匹配、无效值随机修补）的骨架；在此之上，将确定性最近邻匹配改为温度自适应的候选集软采样，并在匹配后引入 swap/insert/reverse 扰动，以缓解固定映射带来的早熟。在**算子层**，直接采用其动态交叉率、与交叉率联动的动态缩放因子、rand/1 与 best/2 混合差分策略，以及 GMR = 1 − CR 的世代间变异，四个算子的公式形式、分支判据与边界取值与原文一致（由保真度测试逐条核验）。
>
> 需要指出的是，本文**未沿用其目标函数与约束体系**：原文以"加权航程代价 + 最坏机飞行时间 + 约束罚项"的单标量加权和为目标，本文因引入任务选择性与完成性约束，改为"物理硬约束—覆盖门禁—迟到软计价—航程与时间"的四层准字典序评价，其负载均衡项作为可选扩展（默认关闭）；原文的协同同时到达约束及其异步初始等待时间替代机制因本文任务为单点独立执行而未引入。此外，本文的实验协议（种群 50、代数 100、3 组随机种子）经独立标定，并非原文协议的复现，两者的绝对数值不可直接比较。
