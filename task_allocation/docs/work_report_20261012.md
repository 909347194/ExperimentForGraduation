## 一、任务链路全景梳理（对照论文第 3 章）

按"产生 → 入池 → 选择 → 分配 → 滚动"五步把代码链路与论文表述逐条对齐：

| 环节 | 代码落点 | 要点 |
|---|---|---|
| **产生** | `common/task_scenario.py` | 合成任务锚定机巢极坐标撒点（15km）、收益 U(1,10)、时间窗按周期倍数生成（`latest = arrival + U(0.5,2)·L`，与滚动时域对齐）；`build_task_batches` 按周期分批到达，可复现 |
| **入池** | `methods/task_pool.py` | `T_t = remain ∪ new ∪ release`；`begin_cycle` 四步（SELECTED 回退、来源归类、过期判罚、冻结 T_t）；周期中到达只进池、下周期才进 T_t |
| **选择** | `methods/selection/` | 五步流水线：基础优先级 P_i(t)（收益/紧迫/等待/协同/代价加权）→ Top-αK 候选预筛 → 可行性 prefilter → 边际收益 ΔB/ΔC 贪心 → 预算 postcheck |
| **分配** | `methods/muas/` | DMDE 外层搜分配+顺序、内层精确解终点机巢；y_j=0 可拒、UAV 可空闲（T_exec ⊆ T_sel ⊆ T_t，U_exec ⊆ U_avail） |
| **滚动** | `methods/rolling/` | 九步单周期编排；完成反馈可行性闸门（违约交付不计完成、回池重选）；故障注入→释放→下周期强制纳入；三类事件驱动重规划 |

产出：论文 3.3（候选任务预筛选）与代码实现的对照结论——排序键 P_i(t)、`k=⌈α·K_avail⌉`、α=2.5 ∈ [2,3]、落选留池均一致；差异点（上取整截断、forced 任务绕过上限、编号漂移）已整理为修改清单。

## 二、方法论评价与自洽性审查

**评价结论：分层框架方法论成立**——问题驱动分解（|T_t|≫K_avail）、指标与挑战章一一呼应、两阶段共享三维代价语义、每步留有消融开关。薄弱点：参数缺推导（权重/α/半径等魔法数）、预筛截断缺质量差距实证、代理失配缺声明。

**自洽性审查结论（三处张力）**：

- **T1（规模决策口径）**：经两轮讨论修正判定——"允许部分无人机保持空闲"是第二阶段的裁量权，一阶段过放行是 filter-then-optimize 的正确偏置，**语义不冲突**；真问题只剩②③吞吐硬上限（`sortie_budget`/`max_participating_uavs`）把可用机**强行压地**时，其航程被计入 B(t) 造成幻影容量记账（见第三(3)项，已修复）。
- **T2（判据口径）**：prefilter 时间窗 ETA 用欧氏距离/速度、其余环节全用三维代价——两套几何已统一（已修复）。
- **T3（表述精度）**：能力规模 min 规则只能向下收编，"规模跟能力走"应改为"双重上界"叙事（αK=复杂度上界、cap(t)=能力上界）；遗留 `pipeline.py` docstring 错句与论文 3.3 公式更新（待办）。

## 三、已完成改进（3 个提交）

### (1) 能力驱动规模：min{αK, 能力预算可承载数} —— `0382747`

新增 `methods/selection/capability.py`：

```
B(t)   = budget_scale · budget_factor · Σ 剩余航程(可起飞子集)
cap(t) = max(min_cap, ⌊B(t) / c̃⌋)     ← c̃ = 粗代价分位数（默认中位）
候选数 = ⌈α·K_avail⌉（与 cap(t) 解耦，能力无关；仅受 max_candidate_pool 计算上限约束）  ← 修订：不再与 cap 取交
选择数 = min(⌈max_ratio·K_avail⌉, cap(t)) ← 能力卡口只在此生效
```

- 粗代价口径与基础优先级 C_i(t) 同源（cost_hint 优先，回退最近可用机距离）
- `forced_task_ids` 仍绕过候选上限；`capability.enabled=False` 退纯机数名额（消融）
- yaml：`selection.capability: {enabled, budget_scale, quantile, min_cap, sortie_budget, max_participating_uavs}`

### (2) T2 修复：可行性判据行进代价口径统一 —— `bb9f790`

- `prefilter` 新增 `cost_hint`：**航程检查与时间窗 ETA 共用同一 travel**（三维代价优先、欧氏回退），消除山区 ETA 系统性低估导致的"放进必然超时任务→完成闸门违约回池"churn
- 新增 5 例测试锁语义（三维 ETA 超窗必须拒、回退行为不变、流水线贯通）

### (3) T1 记账修复：②③被动空闲的航程不计预算（本次）

- `fleet_range_budget` 增加 `sortie_budget`/`max_participating_uavs` 参数：至多 k_op 架可起飞，按剩余航程降序取前 k_op 求和（乐观上界，偏差由 budget_scale 吸收）
- **滚动层自动同步**：二阶段 `MUASStageConfig` 的②③旋钮经 `merge_caps`（取交）注入一阶段能力预算——打开吞吐上限时 cap(t) 自动收紧，无需两处重复配置
- 两处**故意不计入**（有明确辩护）：γ 出动经济性停机（二阶段主动裁量，属架构自由度）；SRP 不变式 K≤M-1（有循环性且任务少时 cap 不受限）
- 新增 6 例测试（②③各自收紧、取交、乐观上界取大航程、流水线与滚动层贯通）
