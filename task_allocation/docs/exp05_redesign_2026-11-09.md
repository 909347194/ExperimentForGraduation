## 0. 为什么要重设计

上一轮结论：现有 exp05 不足以支撑一篇「性能提升」的工作。根因不是跑得不够多，
而是**实验回答的问题与方法主张错位**——方法主张是「把四维设定放进一个可计算、
可审计、可证伪的统一框架」，旧 exp05 却在问「我们的指标是不是比几个启发式高」。

旧设计的 9 项结构缺陷（审计证据，逐条可复核）：

| # | 缺陷 | 证据 |
|---|---|---|
| 1 | 定位错位 | `notes.md`「目的」问的全是「是否明显好于…」；成功标准第 3 条写「M0 在奖励产出率或航程上不低于 B1」——这是排行榜问法 |
| 2 | **主表双源、批次混拼** | `notes.md` 主表 M0 = 0.770 / 1427 km / ≈335 s，D0 = 0.777 / 1265 km；而落盘 `results/summary.csv` M0 = 0.761957 / 1354.95 km / 739.76 s，D0 = 0.774240 / 1348.15 km / 692.22 s。B1/B2/B3/B2e 四行两处一致 ⇒ **本文方法与基线的数字来自不同批次**，违反「同批同口径」公平协议 |
| 3 | 尺子不统一 | D0/B2e 用欧氏自报航程，M0 用 DEM 自报航程，直接并列无意义；且欧氏组连 ETA / 时间窗预筛一起换了，是「换尺子 + 换动力学」双因素，不是单因素对照 |
| 4 | 无独立事后评价器 | 质量数字全部来自各方法**自报**的 `final_path_m` / `final_fitness`；`methods/muas/independent_audit.py` 已实现但 exp05 未接入（exp08/exp09 `notes.md` 亦记为技术债） |
| 5 | 无配对统计 | 只有 `mean±std`；没有同 seed 配对差、精确 p 值、效应量，无法「如实声明不显著」 |
| 6 | 代价不对等且未显式化 | 落盘 `wall_seconds`：M0 739.8 s、D0 692.2 s、B1 2.2 s、B2 2.0 s、B3 2.3 s、B2e 0.4 s（约 3 个数量级）。`notes.md` 却把运行时间定为「辅助列，不作主结论」 |
| 7 | 完成率口径误用 | `notes.md` §「完成率口径」已写「完成率不是性能指标，是正确性不变量」，主表仍把 `η_final` 放首列；B3 的 0.957（硬时间窗主动跳过 18.4 个任务）作为**异口径**方法进了主表并参与排序 |
| 8 | 悬空设计 | v2 写了 B4 CBBA-style / B5 sDE / B6 APSO-LS / B7 EGR 与 2×2 谱系，`baselines/` 里一个都没实现；`arm 级 problem_override` 也没实现。挂着未跑的方法会让论文表格与引言质询同时失守 |
| 9 | 落盘坐标被舍入 | `run.py:solution.json` 的 `tasks[].x/y/z` 用 `round(..., 3)`，而生产 `tour_snapshot` 已按铁律**不 round**（`horizon.py:193-205`）。离线几何重算会跨建筑/DEM 离散边界，重评数字不可信 |

**追加审计（2026-11-09 冒烟时实测）**：旧产物是**三方不对账**——
`notes.md` 主表称「8 巢 × 容量 4、10 机、满电 80 km」，`config.yaml` 实际是
`n_nests: 6` / `uav_max_range: 20000`（20 km）；用当前配置重跑的
`B2@seed42` 自报航程 325.7 km，而旧 `results/summary.csv` 同格是 1597.8 km。
即**旧 CSV 与当前实验配置已不可复现**，不能靠「重新读表」补救，只能重跑。

**另一处实现缺陷（已修，见 §10）**：exp05 自持 `config.py` 把
`coverage_audit` 的默认值写死 `False`（生产 `MUASProblemConfig` 默认 `True`），
且 yaml 未显式给值 ⇒ 审计分账被静默关掉，与定稿 §4.3 冲突；
独立重评实测报 `coverage_audit 未开`。按「审计 FAIL 先怀疑实现缺陷」修装配层
默认值并在 yaml 显式写出，未改任何生产默认值。

因此：**不修补旧表，重设实验**。旧 `results/` 与 `notes.md` 的 v2 实测段落整体
降级为历史存档，不再作为论文主表数据源（见 §8）。

## 1. 方法主张（本实验要检验什么）

五条主张，每条都必须**可证伪**；每条都配「对照 → 指标 → 判据 → 写作口径」。

|---|---|---|

## 4. 统一事后评价器（v3 的核心改造）

### 4.1 要重评什么

所有方法的**交付解**（逐周期 `S_final` 的 tours 几何）用同一把尺重算：

| 量 | 来源 | 说明 |
|---|---|---|
| `f_audit` | `SelectiveMUASProblem.scalar_fitness` | 唯一目标 `f = W_hard·n_hard + w_exc·excess_m + W_skip·n_skip + w_late·L + λ·path`，λ 统一 1e-1 |
| `path_m_audit` | `problem.path_cost` | **DEM 有向**三维航程；欧氏组也用这把尺 |
| `n_hard_audit` / `late_s_audit` / `n_skip_audit` | `hard_stats` / `soft_violation` / `gate_stats` | 重评硬违约、迟到、跳过 |
| `on_time_rate_audit` | 重评 lateness 表 | 独立统计，不用自报 |
| `consistency_equal_all` | 自报 `diagnostics` vs 重评 | 逐位一致断言（§4.3 第 3 条门槛） |

### 4.2 技术路径（零生产代码改动，可落地）

`methods/muas/independent_audit.py` 已提供 `reconstruct_solution` / `independent_audit`，
缺的是「problem 实例拿不到」（exp08/exp09 记为技术债）。v3 在 **exp05 自持目录**内用
两个运行期包装解决，不改 `methods/` 任何默认值：

1. 包装 `SelectiveMUASProblem.from_entities`（classmethod）→ 捕获本次求解真正使用的
   problem 实例（与 `tests/test_p3_independent_audit.py` 同一手法）；
2. 包装 `task_allocation.methods.rolling.horizon.run_selective_muas` → 在一次调用内
   「清空捕获 → 调原函数 → 取 `stage.solution` 与本次捕获的 problem →
   调 `independent_audit(reconstruct_solution(...), problem, reported=stage.diagnostics)`」，
   逐周期把报告追加进列表，随 `metrics.json` 落盘。

**门槛判定的归属**：`independent_audit` 的完成率门槛是**单周期口径**
（`arrived = candidate_task_ids`），在有 `n_skip` / `n_shortfall` 的正常周期会假失败。
故 v3 与 exp08 保持一致：**完成率 / 恒等式 / eliminating 由实验层硬断言承担**，
几何重建重评只用于取**独立数字**与 `consistency`；`independent_audit` 的
`failures` 中除「口径不一致」外不升级为实验失败，但必须原样落盘。

### 4.3 口径修复清单（必须同时落地）

| 项 | 旧 | v3 |
|---|---|---|
| 任务落盘坐标 | `round(x, 3)` | **不 round**（与 `tour_snapshot` 一致，铁律） |
| 航程列 | 各方法自报 `total_path_m`（欧氏组是其自身尺子） | `total_path_m` 保留为自报，**新增** `path_m_audit` / `f_audit` 作为主表唯一比较列 |
| D0 欧氏影响面 | 连 ETA / 时间窗一起换 | **如实标为复合档**，不硬拆生产链路；评价端统一 DEM 重评，并用 §4.4 两把尺子隔离尺子效应 |
| 一致性 | 未检查 | `consistency_equal_all` + 每周期 `consistency` 明细 |
| 主表生成 | `notes.md` 手写 + CSV 两份 | **单源**：所有表格由 `claims_report.json` / `paired_report.json` / `summary.csv` 自动生成，`notes.md` 只引用不抄数 |
| 批次防混 | 配置指纹已有，但手写主表绕过它 | 指纹扩到 `evaluation:` / `claims:` 段；`output_dir` 改 `results_v3/`，旧 `results/` 原封不动 |

### 4.4 两把尺子（C2 的主证据，零额外求解跑批）

旧 exp05 最致命的不是「跑了欧氏对照」，而是**让每个方法用自己的尺子报数**：
D0 报欧氏航程 1348 km、M0 报 DEM 航程 1355 km，两列并排看起来「差不多」，
实际完全不可比。v3 把这件事本身变成证据：

对**同一批交付解**（`solution.json` 的逐周期 tours，坐标全精度），用两把尺子各算一次
总航程，且都按**实际飞行方向**（有向，不做对称近似）：

| 尺子 | 实现 | 输出列 |
|---|---|---|
| `d_DEM`（唯一生产口径） | `VerticalSectionCostEstimator.estimate` 逐腿有向三维航程 | `path_m_audit` |
| `d_euclid3d`（历史朴素口径） | 三维直线距离，同方向逐腿求和 | `path_m_euclid3d` |

报告四件事，全部同 seed 配对（实现见 `claims.py` 的 C2 段）：

1. **尺子绝对差**（口径量级，描述性）：`path_m_audit − path_m_euclid3d`。
   DEM 有向航程 ≥ 三维直线是**定义性事实**，对它做显著性检验没有信息量
   ⇒ 只报量级，不出三态结论；
2. **主判据 `ruler_effect`**：逐 seed 取
   `(M0−D0)@d_DEM − (M0−D0)@d_euclid3d`，检验「换尺子是否**改变方法间差值**」
   （只检验非零，不预设方向）⇒ 配对精确 p / dz / 三态结论；
3. **差值方向是否翻转**：`ruler_changes_direction`（描述性）；
4. **尺子偏差是否因方法而异**：各方法 `d_DEM/d_euclid3d` 比值与 M0−D0 比值配对差
   （描述性）。此项在 v3 初版只写在设计里、代码未落地，正式档前补齐。

**允许的结论**：「在本场景下，把评价尺子从三维直线换成 DEM 有向三维航程后，
方法间差值发生 … 变化（p=…）⇒ 评价口径本身足以改变结论」。
**禁止的结论**：「DEM 让本文方法更快/更短」「D0 单因素导致 X 变差」
（D0 是复合档，且 DEM 航程本就更长）；**「本实验证明求解端必须用 DEM」**
（本实验只换评价端尺子，未做求解端单因素对照）。

这条证据不需要改求解端、不需要新增方法、不需要重跑求解，
只需在 `post_eval.py` 里做几何重算；它是 v3 相对旧 exp05 最有价值的新增。

## 5. 统计协议（与 P4 正式档同规格）

- **seed**：主档 `[42, 43, 44, 45, 46]`（与历史 exp05 同协议，保证可对照）。
  P4 的 `[7, 11, 23]` 是**另一套协议**，跨实验只作描述性对照，**禁止配对 t 检验**。
- **配对**：每个主张指定一对方法，逐 seed 取差；`paired_seeds` / `unpaired_seeds` 显式落盘，
  缺配对即报错，不得静默丢弃。
- **检验**：Student t 双尾**精确** p（正则化不完全 β 连分式，不用正态近似、不依赖 scipy）；
  零方差 ⇒ `p_reason="zero_variance_no_test"`，**不写「不显著」**；`n_pairs<2` ⇒ 不检验。
- **报告量**：`per_seed`、均值、标准差、`t_stat`、`p_two_sided`、`p_reason`、
  95% 置信区间、Cohen's `dz`、`significant_at_0_05`。
- **三态结论**（判据写死，不允许事后改）：
  - `supported`：方向符合主张预期 **且** `p<0.05` **且** `|dz|≥0.5`；
  - `not_supported`：方向相反 **且** `p<0.05`；
  - `inconclusive`：其余（含 p 不显著、零方差、配对不足）。
  - 结论字段必须附 `caveats`：本实验是**单场景、单到达流、5 seed**；
    `inconclusive` 一律写「本实验未检出差异」，**禁止写「无差异 / 等价」**。
- **唯一推断主判据**：`C2.ruler_effect`。其余所有配对（C4 的四指标 × 两对照、
  尺子绝对差、比值差）一律描述性、不产出三态结论；C1/C3 是断言型门槛。
- **多重比较**：多条主张 × 多指标不做事后校正，但须在表下注明「未做多重比较校正，
  名义 p 值」；禁止从一堆 p 里挑一个显著的写成主结论。
